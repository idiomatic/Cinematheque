# Cinematheque

Local-first video libraries. Players on Apple devices, macOS, Linux, and Windows browse shared libraries and play each video from any source that holds it. There is no central server: each library's titles, metadata, and people's data replicate among devices, so every device works offline and catches up when it reconnects.

This file specifies what's built. How operations are encoded, signed, merged, and synced, the HTTP endpoints, and the keys and fields the library writes are in [ARCHITECTURE.md](ARCHITECTURE.md); plans in [DEVELOPMENT.md](DEVELOPMENT.md); outside specifications in [docs/specifications](docs/specifications/README.md). Agents working at once coordinate as `.coordination/README.md` says.

## Lexicon

One word for each thing, in the spec, code, command-line app, and apps; stored keys and fields keep their names as data. The apps show people only the words marked †.

* **Source†:** anything serving videos over HTTP (a NAS, a web server, a folder a device shares); a device's downloads are one, though not listed. Not "repository."
* **Copy†:** a file of an item, in one quality, that a source holds (`held:<source>`). Not "holding."
* **Device†:** a running Cinematheque with keys of its own; the one it syncs with is the other device. Not "peer."
* **Person** (shown as people†): a human, with a key and devices; a member† once admitted. Not "user" (but in what's stored: the `user` seed and fields).
* **Progress:** where a person stopped in an item, and its watched mark. Not "playhead"; how far a long operation has come is its steps.
* **Unavailable†:** a folder that held files and lists none (`absent:`). Not "absent" or "missing."
* **Join†:** a new device coming into a library by a code it shows; a member's device adds† it, as its person's (pairing†) or someone new's. Not "link."
* **Data directory:** a device's own directory of keys and replica. Not "home" (but in the Keychain's `com.rbrian.cinematheque.home` items).
* **Share†:** what a device does with its library and folders.
* **Delete†** takes files off a disk; **remove†** takes something out of a list or the library; **forget†** discards only what's known.
* **Download†:** files coming to the device in hand; in the web client, a file to the browser's computer. **Download next†:** a series' next episodes, as it's watched.
* **Quality†:** one encoding of an item (stored as `rendition`). **Version†:** an edition; **origin:** a quality's Blu-ray, web, DVD, or HDTV token.
* **Sync** and **crawl:** shown as catching up† and looking for new videos†; Refresh Library† syncs, then crawls.

## Components

* [core](core/README.md): the Zig library, and a static library with a C interface ([cinematheque.h](core/include/cinematheque.h), a Swift module by its [module map](core/include/module.modulemap)), documented in [core/include/README.md](core/include/README.md).
* [cli](cli/README.md): the command-line app, `cinematheque`, for macOS and Linux.
* [apple](apple/README.md): one SwiftUI app, `com.rbrian.cinematheque`, for macOS 15+, tvOS 18+, and iOS 18+ on iPhone.
* [tools](tools/README.md): scripts beside the apps, such as [debt.py](tools/debt.py)'s report of code debt.

## Core interface

* **One function per action:** no argument chooses among actions; a caller holding a state picks the function.
* **Arguments** are C's own (arrays as pointer and count, records as structs, kinds as enums with unnamed values refused, an absent integer -1); results are JSON, every string valid UTF-8 (bad bytes as U+FFFD, so no player refuses a whole result). Strings passed in are copied if kept.
* **Threads:** functions belong to one thread, but long ones (crawling, syncing, describing, downloads' configuring, deleting, and reconciling) and reading the whole catalog (`cq_tiles`, `cq_repos`), each on a connection of its own. One connection writes as the device at a time; the main one catches up before acting. `cq_leave` refuses as `Busy` while another connection is open, and none opens while it leaves.
* **Long operations** commit as they go: `cq_data_version` changes when they or a device's push have, `cq_steps` tells how far one has come, and `cq_prioritize` names titles for a crawl to describe first. `cq_crawl_due` crawls only sources no device crawled within the library's interval.
* **Syncing:** `cq_sync` with every device found or added, `cq_sync_with` with one, `cq_sync_known` with those the last sync found, each taking the writer one device at a time; results name each device as it advertised itself, with operations won and pushed.
* The rest (serving, pairing, names, lists, downloads, sources, `cq_version`) are listed in the header.

## Devices

* **Players:** every client, each able to sync and crawl as well as play. Desktop devices (macOS, Linux, Windows) are sources too, sharing their folders and downloads; static servers (a NAS, Caddy, nginx, Apache) run no Cinematheque code.
* **Refreshing:** sync first, then crawl, so what others crawled and described arrives first and the crawl adds nothing unchanged. A crawl records when it was on its source (`crawled`). A refresh not asked for (at launch, or on a timer after a random wait) skips a source any device crawled within the library's interval (`settings`' `crawl`: an hour, 3 hours, a day by default, a week, or Manually, each give or take a 24th, drawn afresh), so a NAS's disks wake no more than chosen; Refresh Library and `crawl` crawl them all.

## Identity and membership

* **Data directory:** `~/Library/Application Support/Cinematheque` on macOS, `$XDG_DATA_HOME/cinematheque` elsewhere, or `--data` or `CINEMATHEQUE_DATA` (the C interface honors it too). It holds `identity` (the device's seed), `user` (its person's seed, if paired as another's device), `library` (its creator's person key), and `replica.db`, made its owner's alone on opening.
* **Keys:** a device's keys derive from its seed, its person's from the person's seed, shared by the person's devices (a device not paired as another's derives one from its own). The person's seed is given to another device only by pairing, and never shown.
* **Pairing:** a new device shows a 6-digit code, serves `/pair`, and advertises `pair` (`new`). A member's device, given the code, has its person choose whose device it is, as their seed would let someone else's device act as them; it sends the library's key and, if its person's, the person's seed, sealed under a key both derive from the code by CPace (ristretto255, SHA-512), so an eavesdropper learns nothing and each attempt tests one guess. The new device answers with its person's key and its own. A new member's person is added. The new device is named, under its person, as it advertised itself until it names itself, never by a generic name (`Not-Your-AppleTV.local` as "Not Your AppleTV", the core's `cq_shown_name`), and shown with its model unless its name says it ("iPhone 13 mini", by [model.zig](core/src/model.zig)). After 3 wrong codes from one address, that address is ignored, and after 30 in all, every address, until it offers anew.
* **Certificates:** a device's first write is its certificate, its person's signature over the library and device key; its private stream has its own. Before writing, once per connection, a device rewrites any of its own missing or invalid, as other devices refuse a stream without one.
* **Library:** its ID derives from its creator's person key. The creator is a member from the start; members add people to a set, and any member may remove any other, the creator too, for good (they return as someone new). No member has powers others lack.
* **Removal:** any member may remove a device, or a member with every device of theirs it knows; a removal only stands or tightens, so none can be undone. Each of a removed device's streams is cut off where the remover had seen it (`revoked`): writes through there stand, later ones are refused, and devices serve it no more. A removed member's device the remover didn't know isn't admitted.
* **Refill:** a device that took later writes before hearing of a removal drops them, and its next pull asks for everything, taking back what they overwrote; a value the device it pulls from lacks too is lost.
* **Leaving:** a removed device is told so at its next sync, by a refusal signed over the library, device, and request time (`removed`), believed only from a signer a member certified and it doesn't know removed. It then forgets the library and its identity (`cq_leave`; on tvOS, the Keychain's seeds and the Top Shelf too), stops the refresh under way, and returns to setup, saying why. `serve` does so too, syncing as it starts; one-off commands only say so. A device may also leave of its own accord: it removes itself, its streams cut just past that removal, syncs so another device takes it (refusing to go on if none is reached, retried without writing again), then forgets. With no one else in the library, it only forgets.

## Replication

How it's done is in [ARCHITECTURE.md](ARCHITECTURE.md); what must hold:

* **Operations** write one field of one key and merge last-writer-wins by hybrid logical clock, ties by device key; `members` merges by causal length, a removal outranking any addition. One dated more than a day past the receiver's clock is refused. No key or field over 64 KiB, nor value over 4 MiB, is written, as others refuse them.
* **Batches** of up to 1,024 consecutive writes are signed once (Ed25519 over library, stream, range, and a BLAKE3 Merkle root), so none can be presented with another range.
* **Storage:** SQLite (WAL; connections wait 10 seconds for one another's writes, as `serve` and `refresh` share a replica) holds each field's winner, interned device keys, signed batches, a version vector, and the device's own state (`local`).
* **Sync** runs both ways, started by either side: a pull, then a push of what the other lacks, so a device behind a NAT syncs both ways. A request is for one device alone, signed, sealed so only the two read it, checked before the rest is read or the replica opened, and answered within ten minutes of the answerer's clock, to members only, under a key salted afresh. A response is believed only from the device asked, for that request, with no batch left out. Bodies are read whole (up to 256 MiB) before applied, so a slow sender holds no write lock. A refused push fails the sync.
* **Admission:** a batch applies only if its device's certificate names a member; else it's held to the response's end, then rejected unclaimed. Refused: operations past a cutoff, cutoffs past any reachable sequence number, private data not from its person's private stream, operations of the wrong kind for their key, certificates but a device's own (or a private stream's, its writer's person's, when none held names another), a shared list's fields but from its owner's devices, and batches overlapping one held. A response's vector is taken only from a member's device, never for the receiver's own streams.
* **Private data** (`p/<person>/...`: progress, lists) is written on each device's private stream, sent only to its person's devices and left out of others' vectors. A device takes its own private stream's batches before their certificate arrives, so one whose replica was lost gets its progress back.

## Library

* **Keys:** `t/<m|s>/<normalized title>/<year or ->` for a title; below it `/v/<edition or ->` (a version, `edition` naming it), `/e/s03e17` (an episode; `/e/s2024e0312` dated, a season a year; `/e/s00-<title>` a numberless special, `title` naming it), `/p/<n>` (a part), and `/r/<quality>`, whose `held:<source>` records the file's path, size, and time, empty once gone. Keys derive from parsed identity, so devices crawling independently agree.
* **Naming:** Plex, Jellyfin, and Kodi conventions and download names: ID tags, years (the last ends a title), editions, parts (after the year or an edition's name), extras, `S01E02`, `1x02`, air dates, season folders (`Season 01`, `Specials`, `Ahsoka Season 1`, `Andor.S02`), yt-dlp's `[youtube-ID]` (a dated name's words before it unread), and Kodi's compact codes (`Show 317 Title`) after the enclosing folder's series title. Dots between digits are a title's (`11.22.63`), as is a scene token that's a word ("Madame Web (2024)") unless beside another token or in parentheses. A name of numbers alone without a year goes unparsed. A numberless file beside a series' episodes extending its name, or in `Specials`, is a special.
* **Qualities:** a file's is its source's, if named; else (`path`) the nearest that says one of its name and its folders up to the source. A name says one by its technical tokens, canonically (`2160p remux hevc hdr`), only with a resolution. A folder says one with a technical token, a resolution and frame rate (`1080p30`), or a frame size, and is taken by its whole name (`HQ 1080p30 Surround`) and not read as part of the file's, unless it reads as a title's (`30 Rock (2006) 1080p`), which gives its tokens alone. Else unknown (`-`). Two files of one quality in one source are numbered (`~2`), shown as "1080p 2".
* **Progress:** per person and item: position and duration in ms, and watched, set in the last 5% or by hand. A position in the first 10 seconds empties position and duration (not the mark); marking unwatched empties them too; removing empties all three.
* **Describing:** after each crawl, one file per movie and season, across sources, describes it unless what it last read is unchanged (its cover's file's size and time, the video's too beside a poster, and describing's version). The best file: a sidecar, then an MP4, then any; of each, a server's before a device's own folder's; a standard version before editions. An MP4 without a cover gives way to the next of its title's or season's that has one, 4 read at most, else it's recorded as none (`tried`). What it was described from is kept while unchanged unless a better file is crawled beside it, and one from a source not crawled now stays while that source does. 16 workers, prioritized titles first, committing every 24 jobs or 750 ms; a network failure is retried next crawl, an unreadable file recorded with no cover. MP4 metadata (texts up to 64 KiB, 256 atoms a level) fills a title's `description`, `genre`, `released`, `network`, and `sort` (`sonm`, `sosn`), and an item's `title`, `description`, and `duration`. Other episodes and versions are described on demand, and on a Mac by a sweep as File › Describe All Episodes asks (a toggle, unchecked to stop, resuming where it stopped; `cq_describe_all`): every item no describing read, from an MP4 (a server's first, none unavailable), titles begun first, 4 workers, none beginning while a stream plays, beside other operations, its progress apart (`cq_describe_steps`), stopped before leaving (`cq_describe_stop`). Each item records the file read (`read`), so players describe it again once it changes (`described`).
* **Covers:** a sidecar image by Plex, Jellyfin, and Kodi convention, else an MP4's, found by range requests walking atoms to `moov` (about 8). A cover is recorded as a byte range (`art`, `art:s01`...), fetched by one range request; images don't replicate. Its shape does (`shape`, `shape:s01`...: a JPEG's width and height from its frame header, or `-`), so players lay covers out before they load; one described without it gets it by one range request.
* **Tiles:** a movie or a season (a season without a cover takes its series'), with this person's progress: watched if every item is, else the share of running time played (watched items whole; unknown lengths the average), elapsed and runtime; how many items; whether any is begun; and its title's place in each order ([order.zig](core/src/order.zig)): by `sort`, else name less a leading article, without case or accents, numbers as numbers, then year; release (`released`, else year); when added (`added`, written once by a crawl finding it in a source crawled before, else its files' earliest modification time); when last modified (its files', not downloads'); when this person's progress last changed. A series' seasons share its place; a title with none goes last.
* **Lists** ([lists.zig](core/src/lists.zig)): per person, private like progress, named sets of titles. `p/<person>/lists` names each list by ID (16 random hex digits, emptied once deleted, for good); its titles are at `p/<person>/list/<id>`, a movie by title key or a season by `<title key>#<season>`, `1` while on it. The Watchlist keeps its titles at `p/<person>/watchlist` (ID `watchlist`), named "Watchlist" until renamed.
  * A placeholder is a title not in the library yet, `w<TAB>name<TAB>note`, keyed as its file will be, so it's on the list as it comes. Only the command-line app adds and removes them (`want`). Players show one as a dimmed "Not in library" tile (the web client opening a note that's an address; the Mac's inspector and the Apple TV's page showing its details); the Top Shelf leaves them out.
  * Shared with every member (confirmed first), a list's titles move to `l/<owner>/<id>`, beside its `name`, taken only from its owner's devices. Its mode is a log (`mode:<random>`, `shared` or `private`, each written once, the latest current). Made private again, its titles go back and the public copy is emptied, hiding it, not recalling it. Others' shared lists show after a person's own, read-only, as theirs ("Avery's Watchlist"), marked with two people; only one's own are in Lists menus and star a title.
* **Names:** `n/<key>`'s `name` (and a device's `user`, its person), set by any member, shown in place of keys. A device's `served` (where it serves its own folders) and `model` (from which the core tells its kind, for its symbol) are taken only from that device, written as it starts if changed.
* **Views** ([views.zig](core/src/views.zig), for the C interface and the web client): what players show comes named and decided: a title's items in order (episodes by number, specials last) and seasons; which item Play plays (the latest in progress, else the first unwatched after the last watched, else the first unwatched, else the first); each quality's resolution, for ranking; items' labels ("Episode 3", "Special", "March 12", a version's name, "Part 1"); and each quality's short name ("4K HDR", Other if unknown), adding what else its full name says only where two read alike, options only if nothing else tells them apart.

## Sources

* **Shown** as the core names them: server (host without `.local` or port) and folders, decoded, a NAS's shared folder left out past two ("sulaco › Video › TV Shows"), the last folder by its owner's `name` if given; devices' downloads last. Removing a device removes its downloads.
* **Settings:** a source is a URL (percent-encoded as typed; http or https with a host, no query or fragment, else taken for none), or a device's own folder's, port-free: `cqdevice://<its key>/<path>`, taken only from that device and reached where it says it serves (`served`), so a new port is one field. A crawl skips one whose device hasn't said where (`away`). It has where its quality comes from (`path`, or a name: `quality-by`, `rendition`; one this device doesn't know keeps it uncrawled) and a prefix of names to skip, applied at the next crawl. Its ID hashes its URL, which its `url` must match (or be empty), standing from the device that wrote it, the only one whose `managed` is taken. Removing it clears its settings and copies everywhere.
* **A device's downloads:** a source of its own, `managed`, never crawled (the Mac app's). A device marks it again whenever configuring finds the mark no newer than its address, as a mark arriving first would be refused. Each file fetched is recorded as its copy in the quality it came from, and in the device's `local` (path, quality, size), which it plays, marks, and deletes from first. Files go under their source paths, into `<path>.part` resumed by range, never past their size, only within the folder, with nothing hidden along the path, never replacing another size's file but its own. It deletes, keeps, and forgets only copies it recorded. No download begins while a stream plays. One whose copies are all away waits, unsaid. One under way that stops being wanted stops at its next mebibyte, its `.part` deleted.
* **What a device keeps** is its own (`local`): items wanted by hand, kept until deleted, and per series a choice: the next N (the latest in progress and the N unwatched after it, else the first N; specials out) or `all`. A title or season wanted is its items as of then, each in the picker's quality, or the nearest lower, else higher.
* **Done with:** a series' download watched since fetched, unless wanted by hand or all chosen, is deleted at the next reconcile if another source holds it alike (quality, size, not unavailable); the only copy, never. Reconciling forgets copies whose files are gone, and leaves 20 GB free.
* **Listings:** an `INDEX` if there is one (a path per line, optionally tab-separated size and time; a directory's ends in `/`), else JSON (Caddy's, nginx's), else HTML links. No name with an empty, `.`, or `..` segment, a segment over 255 bytes, a path over 4 KiB, or a control character, nor over 4 million entries.
* **Crawls:** breadth-first, 16 workers by default, then the source's copies brought in line. A directory whose files' times are unchanged reuses its last listing, but in a full crawl. Up to 3 redirects, within the source's origin; no other request follows one. A crawl that fails anywhere changes nothing.
* **Unavailable:** a directory still listed but holding none of the files it held is one field (`absent:<directory>`, the topmost), its copies kept, cleared once it lists files, once it's gone from its parent (its copies going), or a year on. A person may remove its copies. Players dim a title whose copies are all unavailable, and try those last.
* **Time limits** ([deadline.zig](core/src/deadline.zig)): a request's head, 30 seconds (and a body's rest a mebibyte a minute); a listing, 2 minutes; a cover's or MP4's range, 1 minute; a sync, 10 minutes, its `GET /sync` 10 seconds and each response's head 2 minutes; a download, a minute to answer and a minute a mebibyte. A server takes 256 connections, 32 from one address (counted by a hash seeded afresh).
* **Serving:** on the port given, else 8008, else any free port, advertised; on `::` with IPv4 mapped; `SO_REUSEADDR` alone, never `SO_REUSEPORT`. A connection opening with a TLS handshake is closed at once, so a browser falls back to HTTP.
  * `/sync`, and `/version` (JSON: `app`, the command-line app or `macOS app`, `tvOS app`, or `iOS app`, as two on one computer can't otherwise be told apart; `version` from [Version.xcconfig](apple/Version.xcconfig), `revision` by `git describe --tags`, `-dirty` if a tracked file but [CHANGELOG.md](CHANGELOG.md) differed, `mode`, `zig`; nothing of the machine or library).
  * Media directories, each at its own path (`/media/`; the apps' by folder): single byte ranges, `If-Range`, `mtime-size` ETags, nothing hidden served or listed, listings as JSON or HTML. The command-line app's has an `INDEX`, rebuilt on a request once a minute old or once the computer's volumes change (the mount table read every 2 seconds), and `serve` crawls its media as they change. The apps' folders have none; one not there lists empty, so a crawl finds it unavailable.
* **Discovery:** `_cinematheque._tcp` by DNS-SD (Bonjour; Avahi's compatibility library on Linux), named `cinematheque-` and the device key's first 8 hex digits. A device skips itself (and its renamed second process) and removed devices. TXT: library ID, sync path, person's key, device's and person's names, for display only, never admission. At most 64 services, resolved within 4 seconds, before the write lock. A new device advertises `pair`, its path, and name instead. `CINEMATHEQUE_DNSSD` gives another type (the mock library's `_cinemock._tcp`).

## Command-line app

* **Commands:** [usage.txt](cli/src/usage.txt) lists them, and is their help. State commands are `NOUN VERB` (`list`, `show`, `add`, `set`, `remove`) over `person`, `library`, `member`, `device`, `source`, `title`, `progress`, and `want` (placeholders); actions are single words (`crawl`, `sync`, `serve`, `refresh`); options are named; `ls` and `show` stand for `title list` and `title show`. Devices join only by code; an offer prints its code and port, for `pair CODE URL`.
* **Usage:** placeholders in capitals, named for meaning. `-h` shows usage, of a noun or action if given; a bad command line shows it and exits 2. Failure says why in words on stderr, saying what to do, never a trace, exiting 1. Output shows control characters but newlines and tabs as `?`.
* **Added addresses** (`device add URL`, for a device beyond Bonjour's reach) are kept in `local`; `sync` and `refresh` use them with those found.
* **Web client:** `serve` serves one at the root (plain HTML, CSS, JavaScript, and the app's icon) unless `--no-web`. A browser acts as this device's person, so only one on this computer may (a loopback request, or an SSH tunnel's), unless `--permissive`. Details are in [cli/README.md](cli/README.md#the-web-client-in-detail).
  * **Setup:** with no library it serves anyway, syncing off, offering Create a Library or Join a Library by code (offered at `/pair` on its port). Once it has one, it names itself by the computer's name, advertises, and syncs.
  * **Settings** on one page, as the apps': names; people (removed, or added by code); this person's devices (last seen, renamed, removed, added by code, those nearby listed as found, or by address); sources (but devices' downloads), with counts, opening, and removing; a server's address, or the one folder `--media` serves, added; unavailable folders' videos removed; the crawl interval; Refresh Library (or Fully); and Leave This Library, as the apps leave. Actions are symbols at a row's end, words for what starts a flow. Setup's changes take a lock before the writer, never after; the library and identity have a lock of their own.
  * **Layouts** by window width: wide, the Mac's sidebar (Movies, Series, Watching, Watched, then a Lists heading with ⊕ and each list), search top right; narrow, the iPhone's tab bar (Home, Movies, Series, Lists, Search), Home being a link to Watched, Continue Watching, and a row per list.
  * **Pages** have addresses (`#movies`, `#lists/<id>`, `#title/…`...), so Back retraces them and a title is a real link. Rows give covers one height, each its shape's width (snapped to 2:3, square, 4:3, or 16:9); grids give cells the column's width. Shelves are the Mac's, with Group by Series opening a series' seasons on a band below its row; a list's page has Rename, Share, and Delete. Orders are kept per browser. A shelf keeps its place when shown again, redrawing only changed tiles where its makeup is the same.
  * **Title pages and playing** as the apps', of what browsers play (MP4, M4V, MOV; HEVC where supported), with the browser's own controls. **Download** brings an item's file to the browser's computer through the server, resuming by range.
  * **API** under `/api/`: the apps' JSON, covers fetched by the server. Only URLs within the library's sources are fetched, raced, or noted lost, covers without redirects. It answers only by a host no other site can take (an IP address, `localhost`, a `.local` or single-label name, the computer's own), only its own page, changes as same-origin JSON, nothing framed or sniffed. A second after a browser's last change it syncs, one device at a time; an unreachable device is said once until it answers. A relayed file failing once begun drops the connection.

## Apple players

Details, as built, are in [apple/README.md](apple/README.md#in-detail).

* **Structure:** one multiplatform app (a shared model, playback, title presentation, shelves, and setup, each platform's browser apart); one target, whose build phase links the core as one object exporting only the C interface; on tvOS, the Top Shelf extension.
* **Title presentation:** names as the core gives them; a season "Season 3", a dated series' by its year alone; a quality picker by short names, the full name as help. Lists is a menu of every list, each checked if the title's on it, then New List…, its star filled if on any. The watched mark toggles by pressing. Start Over, before Resume, is the one way to start over.
* **Tiles:** a cover's corners spared; progress a thin white bar on a translucent track along its foot; under it, the name (wrapping to two lines where a row has room) with its marks at the line's end, a tile as wide as its cover. Marks are one way everywhere: downloaded, a blue arrow (Mac); on a list, a yellow star; watched, a green check. An item's row has its marks before its runtime (as wide as the list's widest) and a thin bar under its name while partway. A series' tile shows its season to watch's cover and its progress over every season.
* **Shelves:** Home (the Mac's Watching in its place), Movies, Series, Lists, Watched, in the core's orders (by when last watched for Watching, Watched, and Continue Watching; else by title), with search, counts, and empty text. A tile's context menu has Lists, and Mark as Watched and Unwatched (a whole series' on the Apple TV's series tiles).
* **Setup:** Create a Library or Join a Library, showing a code a digit to a box in two groups of three: on the Mac, a welcome window; on the Apple TV, large choices. No app shows or takes keys.
* **Playing:** fading in from black as sound rises once ready (resuming 4 seconds early), out as it falls on leaving; position saved every 10 seconds past the first 10, on pause, and on leaving; watched at the end; then the next item.
* **Copies:** a Mac's download plays first; else the chosen quality's available copies are raced (`cq_race`), one that failed lately tried last. A copy that doesn't load gives way to the quality's others, then other qualities', the nearest at or below its resolution first. An item lacking the chosen quality plays the first of those, the Mac's inspector naming it dimmed.
* **VLC:** a copy Apple's players can't play (MKV, ISO) goes to VLC if installed ("Play in VLC"): on the Mac, opened in it; on the iPhone and Apple TV, by its `vlc-x-callback://` link (the Apple TV's `x-success` a `cinematheque://` link back). No progress is saved.
* **Sharing:** while running, the apps share the library (the Mac its folders) on their last port; sync quietly a minute after they last did, on coming to the front, and a second after their person's change; and reload when a device pushes to them. A device out of reach isn't said to have failed.
* **Changes while busy:** a change refused as busy waits its turn, in order, and is made once the writer's free; leaving drops what's waiting.
* **Reading back:** after a change, the catalog is read back off the main thread, the latest read winning; a tile's watched mark shows at once. Only launch, pairing, leaving, and a refresh's end read on the main thread.
* **Addresses from other devices:** only http(s) addresses are opened or fetched as covers (no more than the cover's length), and only paths within a folder shown in Finder or played.
* **Adding a server:** by its address, `http://` added if left off.
* **Settings** (iPhone and Apple TV), one set of pages: this device's name and its person's; People (removed by pressing, confirmed) and Your Devices (by kind and model, last seen; each a page, renamed, or removed but this one), each ending with devices offering nearby, one chosen taking its code; sharing; Sources, with counts, paths ellipsized in the middle, each a page (address, quality, prefix to skip, unavailable folders with Remove Videos, removing confirmed); Add Server (address, quality, prefix); Refresh Library; Look for New Videos; Leave This Library…, confirmed.
* **Settings' notes** say why one would use a setting, then what bears on choosing it; a confirmation says what an action does.
* **Modelessness:** dialogs only to confirm what's hard to undo, or where a platform has no other way to ask; names and settings typed in place; what's easy to undo done at once. Every flow has a way back out.
* **Project:** Xcode's recommended settings but script sandboxing, the App Sandbox, the hardened runtime (until signing for distribution), and the macOS 15 minimum. Signing is in [Signing.xcconfig](apple/Signing.xcconfig), a developer's team in an ignored `Local.xcconfig`. [Info.plist](apple/Cinematheque/Info.plist) allows plain HTTP and local Bonjour, and declares `cinematheque://` on tvOS only.

## macOS player

* **Sidebar:** Movies, Series, Watching, Watched, and Downloaded; then Lists (made by its heading's ⊕, File › New List ⇧⌘N, or a tile's Lists › New List…, each named in place); renamed in place, shared, and deleted (confirmed) from its context menu or the File menu; then others' shared lists. The last shelf shown is shown at launch. View › Sort By sorts the shelf shown, per shelf, starting at the top.
* **Grid:** covers in fixed cells, rows placed before they're drawn, so the scroll bar holds still. Movies 2:3; seasons square under their series' name.
  * **Group by Series** (View, on by default, Series shelf only): a tile per series, saying how many seasons (or which, of one, but nothing for a first season alone; a dated series' years) and its year, if its name has one.
  * **Bands:** the selected series opens below its row, its seasons on a tinted band pointing up at it, one at a time, closed by clicking again or Escape (a series of one season being that season's tile). Opening and closing animate (none under Reduce Motion), then the grid scrolls to show the band. The grid keeps room for the tallest band ("This space is intentionally left blank."), so its height never changes.
  * **Tiles:** a whole name as help when cut short; a color of its own until a cover loads (with the title, if it has none).
* **Keys:** the covers have the keys at launch; ⌘F focuses search. Arrows move the selection, scrolling just enough; on the Series shelf, over series (each opening as reached), into its band, and out of its ends and edges. Return plays, as double-clicking does. Each shelf keeps its place by its topmost title.
* **Inspector:** a series': its cover, watched mark, Play or Resume for the season to watch (named), facts, description, and its seasons, each with progress and episodes. Else the tile's cover; a quality picker above Play (text, with one quality), starting on the best Play plays; the marks on the name's line; Play or Resume, Start Over before it; metadata; versions or episodes, each playable, described on demand. Its width is the person's, kept, 300 points at least, no row wider, so choosing a title never reflows the grid.
* **Downloading,** each in one row where nothing appears or disappears:
  * a movie's Download with its size (the version Play plays; all its parts; the quality, dimmed, if not the picked one), Control-click listing each quality with its size, a warning if it wouldn't fit, or a clock if all its copies are unavailable ("when Archive1841 is back", still choosable), one coming being its Cancel; or a season's pop-up of the series' choice (Nothing, Next, Next 3, Next 10, All, with sizes, then the space available);
  * a gauge while it comes; Show in Finder, or Open in Browser if only servers hold it, its context menu listing every place; and a trash button, canceling or deleting (deleting what the series' choice asks for sets it to Nothing).

  A size is orange if what of it isn't here wouldn't fit. Free space is the disk's; available, free less what downloads keep free. Items' rows and movie tiles have the same in their context menus.
* **Crawling** fills the grid as it commits, tiles on screen described first.
* **Playing** in the library's window, Back or Escape returning, or with ⌘ in a window of its own; its title row only with the controls; Space, F, M, C (captions), and arrows (10 seconds) as in QuickTime Player; the display kept awake.
* **Settings:** four panes (People, Devices, Sources, Downloads), nothing behind an Advanced toggle, text buttons without symbols. At launch the app names this Mac and you if unnamed.
  * **People:** members; you renamable in place, others removable; Leave This Library…, closing Settings for the welcome window.
  * **Devices:** yours, by kind's symbol and when last seen, renamable, and removable but this Mac; sharing; New Devices, each with boxes for its code, then Yours (the default) and Someone New; a wrong code shakes the boxes clear.
  * **Sources:** Add Folder… and Add Server…; Look for videos; each with Show in Finder or Open in Browser, and Remove. This Mac's folders are served while it runs, each at its own name, encoded (`/TV%20Shows/`), by port-free addresses; one not there is shown unavailable and crawled as volumes mount or unmount (and every minute), so its copies are marked at once. A source's sheet has its address or folder (with Show in Finder and Choose…, another folder at the same address), its quality (From Names and Folders, or Named), the prefix to skip, and unavailable folders with Remove Videos. A folder overlapping the downloads folder is refused, as is a downloads folder overlapping a source's, as its records would count as copies held elsewhere and an only copy could be deleted.
  * **Downloads:** the folder (`~/Movies/Cinematheque` unless chosen), served at `/downloads/`; what it holds and the space free; progress of only what's to be fetched; the rule for what goes.
* **Toolbar:** the sidebar's toggle far left (⌃⌘S) and the inspector's far right (⌃⌘I), in one place whether it's open or not; over the grid, the shelf's title, its action (Downloaded's Show in Finder; Watched's Forget Watched…, marking it all unwatched), and AppKit's search field. The window is at least 960 points wide, the grid at least 480, the sidebar at most 320. The inspector is outside the split view, attached only while shown.
* **Refreshing:** File › Refresh Library (⌘R), its ⌥ alternate Refresh Library Fully (⌘⌥R); then Describe All Episodes, a toggle. At launch, the app shares, syncs, names itself if need be, then crawls, syncing before writing anything, so a device whose replica was lost learns its writes back first.
* **Status bar,** floating along the grid's foot, faded before the widest scroll bar's column: counts or what went wrong; what's running, with progress, else the sweep of episodes ("Describing 1,240 of 19,600 episodes…"). It fades 3 seconds after changing, unless something runs (but the sweep, asked for and long) or is wrong, and returns as the pointer nears.
* **Tooltips:** short fragments without a period, saying only what the control and text don't.
* **Modelessness:** no alert nobody asked for. Confirmed first only: removing a source (saying how many videos go, everywhere, files untouched), removing someone, leaving, forgetting what's watched, and deleting the only copy. What goes wrong shows in the status bar and along Settings' foot, in words, each source by name, until dismissed, the next action of its kind succeeds, or the library changes.

## iPhone player

* **Data directory:** the app's Application Support.
* **Shelves:** a tab bar of Home (Continue Watching, a row per list with See All, Settings from its corner), Movies, Series (a justified layout of covers per series, each opening its seasons), Lists (New List named in place in the navigation bar; a list's page renamed in place by its title, its title's menu sharing and deleting it), and Search. Rows are carousels; grids give cells the column's width.
* **Pages:** a movie's or season's, its cover in its own shape, Play or Resume, Start Over, quality, Lists and watched mark, versions or episodes; a season's neighbors (‹ ›) in the navigation bar.
* **Playing:** full screen in AVKit's player, fading in and out.
* **Settings:** a sheet of grouped pages, fields typed in place, removing by swipe too, a code on the number pad; a source's address opened in Safari; Add Server… a sheet.
* **Not yet:** its own setup (the Mac's welcome form, full screen); downloads.

## Apple TV player

* **Data directory:** in the caches, which tvOS may purge; its seeds are kept in the Keychain too (this device only) and put back at launch, so a purge loses only what syncing and crawling rebuild.
* **Refreshing:** at launch, naming itself if unnamed, sharing, syncing, then crawling.
* **Home:** a home page, one stack of pages from it, Back retracing them and leaving from it. At the top, the sections' buttons (Movies, Series, Lists, Watched, then Search and Settings as symbols), focus on the first; then Continue Watching, and a row per list under its heading, its link ("Favorites 3 ›"). Rows are carousels, each cover its own shape's width.
* **Sections:**
  * **Series:** a cover per series, opening a page of its seasons: Play or Resume for the season to watch, focused first, the series' watched mark, then its seasons in square cells, specials last. A series of one season opens it.
  * **Lists:** every list's row, its heading opening the whole list as a grid, with Rename…, Share… or Stop Sharing, and Delete List… on one's own (naming on the full-screen keyboard); New List last.
  * **Grids:** six covers to a row as tvOS's lockups, a season's whole in its own shape at the foot of a 2:3 box, so names line up; Series and Search a cover per series.
* **Play/Pause on a tile** plays what its page's Play would, at once.
* **Settings,** as tvOS's Settings app: the app's icon left with the focused row's explanation (its section's note unless its own; also its VoiceOver hint); a grouped form right, centered while it fits, plates of one height, uppercase headings; at accessibility sizes, values under titles. A row is pressed: text and codes on the full-screen keyboard, a setting's choices a page, unavailable folders' videos removed; Add Server a page.
* **Top Shelf:** Continue Watching, then each list (a dozen each), with covers or the app's drawn stand-ins, written to the app group's `Library/Caches` (`group.com.rbrian.cinematheque`) at once with covers at hand, then again as the rest arrive. An item opens its title's page (`cinematheque://title?tile=…`), presented over the app without a transition, Back closing it; with Play/Pause (`&play=1`), it plays at once, the page black beneath until left.
* **Pages:** over a blurred backdrop of its cover: the cover in its own shape, the series' name and season's, the seasons before and after as buttons in its top corner ("‹ Season 6", "Season 8 ›"), moving in place; Play or Resume focused first (details read before drawn), Start Over, Quality, Lists and watched mark; then versions or episodes. The quality is the best it plays (MP4, MOV, M4V; up to 2160p on a 4K display, else 1080p) unless one's chosen.
* **Playing:** full screen in the system's player, UIKit's large white spinner centered on black until it shows; its picture fades in once the display has switched to the video's frame rate and range and it's playing. Back fades it out, restores the display's mode behind black, then fades the page in. In the background it pauses, and returns paused.

## Debugging

* The apps log under `com.rbrian.cinematheque`: playback steps' times (`playback`); each Top Shelf written (`topshelf`); each sync's exchanges that changed something (`sync`); and each crawl's sources and describing (`crawl`).
* Debug builds take launch options (`open --env` in a VM; `SIMCTL_CHILD_`-prefixed in simulators): `CINEMATHEQUE_DATA` (a data directory to run on; on tvOS, the Keychain untouched), `CINEMATHEQUE_SELECT` (a tile or series to open), `CINEMATHEQUE_TAB` (a tab, section, or setup's `join`), and `CINEMATHEQUE_APPEARANCE` (`dark` or `light`). Any build: `CINEMATHEQUE_DNSSD` (see Discovery) and `CINEMATHEQUE_DOWNLOAD_FLOOR` (the free space downloads keep, for a VM's disk).

## Implementation

* Zig 0.17+ for the core and command-line app, depending on nothing but the system's SQLite and DNS-SD. Whatever waits does so through `Io`, so it can be canceled; only SQLite's disk I/O and the system's name lookup block outside it (copy racing looks names up through DNS-SD on Apple platforms).
* Releases are ReleaseSafe, never ReleaseFast, as they parse what others send. The apps' debug builds build the core ReleaseSafe too, as Zig 0.17's `std` panics in Debug on an interrupted connect (EISCONN).
* **Versions:** one, `MARKETING_VERSION` in [Version.xcconfig](apple/Version.xcconfig), for the Apple app and the command-line app (read by its `build.zig`); the core takes its version from its builder (`-Dversion`). A release is a tag `v<version>`, its commit renaming [CHANGELOG.md](CHANGELOG.md)'s Unreleased.
* **CI** ([.github/workflows](.github/workflows)), on pushes and pull requests but documentation-only ones: the core's tests; the command-line app ReleaseSafe and [cli/test.sh](cli/test.sh) on Linux and macOS (allowed to fail on macOS, for Local Network privacy); the Apple app for macOS and the tvOS and iOS simulators. On a tag matching the version: a GitHub release, its notes the changelog section ([release-notes.sh](tools/release-notes.sh)), with the command-line app for macOS and Linux on aarch64 and x86_64 (`.tar.gz`, SHA-256 checksums) and the Mac app, signed ad hoc, zipped.
* Tests: the core's (`zig build test`), [cli/test.sh](cli/test.sh) (devices end to end), and screenshots on the mock library ([screenshots.sh](tools/screenshots.sh)): the Mac in a macOS VM (terrarium's `macos-27.2-quiet`), the Apple TV in the tvOS simulator (Apple TV 4K, 3rd generation). Simulators named `Mockup …` run the mock library; `Production …` ones are the developer's, which no script touches.

## Scale

100,000+ video files: 4,000+ movies, and 500+ series of up to 30 seasons of up to 50 episodes.

## Risks

* App Review may resist a library that encroaches on Apple's own, more so one that serves media.
* Outside metadata providers' sources' terms (TMDB's commercial charge, IMDb's personal-use datasets) bind them, not Cinematheque.
* GPL tools (`HandBrakeCLI`, GPL FFmpeg) must run as separate processes, never linked.
