# Apple players

The players for Apple devices, in SwiftUI, on the [core](../core/README.md) through its C interface:

* **macOS** (macOS 15 or later): sets up and manages a library, browses it by cover art, and plays copies straight from their sources, keeping the person's progress and lists. It opens this device's data directory (`CINEMATHEQUE_DATA`, or the default), which it shares with the [command-line app](../cli/README.md).
* **Apple TV** (tvOS 18 or later): pairs as a person's device or joins their library, syncs with devices and crawls the sources itself, browses by cover art with the remote, and plays full screen, keeping progress by the same rules.
* **iPhone** (iOS 18 or later, a prototype): browses a library it's given by cover art, by a tab bar, and plays full screen; setting up, Settings, and downloading are still the Mac's and the Apple TV's.

## Building

Open [Cinematheque.xcodeproj](Cinematheque.xcodeproj) in Xcode and run the Cinematheque scheme on My Mac, an Apple TV, or a tvOS simulator; Product › Show Build Folder in Finder finds the app in DerivedData. Or, from the command line:

```sh
xcodebuild -scheme Cinematheque -configuration Release build
open "$(xcodebuild -scheme Cinematheque -configuration Release \
  -showBuildSettings | sed -n 's/^ *BUILT_PRODUCTS_DIR = //p')/Cinematheque.app"
xcodebuild -scheme Cinematheque \
  -destination 'generic/platform=tvOS Simulator' build
xcodebuild -scheme Cinematheque \
  -destination 'generic/platform=iOS Simulator' build
```

The project is in Xcode 27's format ([project.xcproj](Cinematheque.xcodeproj/project.xcproj), readable JSON, converted with `xcodebuild -convert-project "Xcode Project"`), so it needs Xcode 27 or later. It has one multiplatform app target, Cinematheque, for macOS, tvOS, iOS (iPhone only, `TARGETED_DEVICE_FAMILY` 1), and their simulators; settings that differ by platform are conditioned on the SDK (e.g., `[sdk=macosx*]`):
* **Sources:** the [Cinematheque](Cinematheque) folder, which Xcode keeps in sync, so new files need no project edits: [Shared](Cinematheque/Shared) for every platform, and [macOS](Cinematheque/macOS), [tvOS](Cinematheque/tvOS), and [iOS](Cinematheque/iOS), each file of which is wrapped in `#if os(macOS)`, `#if os(tvOS)`, or `#if os(iOS)`. A view each platform has its own of shares one type name (`Browser`), so shared code names it once; its files carry a platform suffix (`Browser+tvOS.swift`), since a target can't compile two files of one name.
* **Core:** the build phase runs [build-core.zsh](build-core.zsh), which builds the core with Zig (from `/opt/homebrew/bin` or `/usr/local/bin`), ReleaseSafe, for the platform (macOS, tvOS, iOS, or their simulators, with the SDK as sysroot) and each architecture being built, so Release builds are universal. It links each into one object exporting only the C interface (`ld -r -exported_symbol '_cq_*'`), since the compiler runtime Zig bundles (which the core needs for 128-bit floats) would otherwise clash with Xcode's. Swift imports it as `CCinematheque`, by the [module map](../core/include/module.modulemap) beside its header.
* **Bundle:** [Info.plist](Cinematheque/Info.plist), merged into the generated one, allows plain HTTP and Bonjour (`_cinematheque._tcp`) on the local network, where sources and devices are. Preprocessed (`#if TVOS`, defined for tvOS's SDKs), it declares the `cinematheque://` links the Top Shelf opens, on tvOS only. [Assets.xcassets](Cinematheque/Assets.xcassets) holds placeholder icons drawn by [draw-icons.swift](draw-icons.swift) (a cinema-red gradient and the `film.stack` symbol): the Mac's, on its icon grid (a rounded square 824 of 1,024 across, since macOS sets a full-bleed square on a gray plate), and the Apple TV's brand assets (its icon in two layers for parallax, the Top Shelf, and Settings' picture, `SettingsIcon`). A compiled catalog matters beyond looks: without one, tvOS's search keyboard faults looking for it (CoreUI's "unable to find a bundle").
* **Scheme:** shared, with `CINEMATHEQUE_DATA` ready but disabled, for running on another library, and `CA_DEBUG_TRANSACTIONS`, off, to log where Core Animation is used off the main thread.
* **Settings:** Xcode 27.2's recommended ones (its macOS app template's) but for four, on purpose: script sandboxing is off, as the core's build phase reads `../core` and Zig's cache; there's no App Sandbox, since the app shares this device's data directory, in `~/Library/Application Support`, with the command-line app; the hardened runtime waits for signing for distribution; and the app runs on macOS 15 or later. Swift code is isolated to the main actor by default, with approachable concurrency; what crosses threads (the core's handle, decoded images) is marked `nonisolated`.
* **Signing:** on the Mac, ad hoc; on tvOS and iOS, automatic, so the simulators need no team, and an Apple TV or an iPhone needs a `DEVELOPMENT_TEAM`. It's set in [Signing.xcconfig](Signing.xcconfig), not the target, since Xcode's Signing editor writes into the target, whose settings outrank the file (a team left blank there hides the developer's). A developer's own settings, such as `DEVELOPMENT_TEAM`, go in `Local.xcconfig` beside it, which it includes if present and Git ignores, so they stay out of commits. If Xcode writes signing settings into the target again, delete them there.

## Sources

Shared:

* [Library.swift](Cinematheque/Shared/Library.swift): the library through the C interface (its state, setting up, and calling the core), its parts in extensions by area: [Library+People.swift](Cinematheque/Shared/Library+People.swift) (pairing, names, and devices), [Library+Sources.swift](Cinematheque/Shared/Library+Sources.swift) (sources, folders on this Mac, serving, and refreshing), [Library+Downloads.swift](Cinematheque/Shared/Library+Downloads.swift) (the Mac's), [Library+Sync.swift](Cinematheque/Shared/Library+Sync.swift) (keeping in sync, and saying so), and [Library+Progress.swift](Cinematheque/Shared/Library+Progress.swift) (this person's). It decodes JSON into the types [Models.swift](Cinematheque/Shared/Models.swift) holds (status, tiles, a title's details, sources, members), and runs long operations (crawling, syncing, describing) off the main thread, reloading as they commit. What goes wrong becomes `problem`, a sentence (a long operation's first failure, by its server's name, and how many more), with its kind, so only a success of the same kind clears it.
* [ArtCache.swift](Cinematheque/Shared/ArtCache.swift): covers fetched by range request, scaled with ImageIO off the main thread (480 pixels for tiles, 1,200 for larger covers), and kept in memory and on disk (the app's caches, `com.rbrian.cinematheque/covers`). Until one loads, its placeholder shows: rendered by the core from its ThumbHash and scaled up, or, without one, a color of its own with its title. A cover replaces it at once (a fade, tried at 3, 0.3, and 0.1 seconds, wasn't worth it); one in memory shows from the start, so scrolling back shows no placeholder.
* [Playback.swift](Cinematheque/Shared/Playback.swift): what to play (`PlayRequest`), and the queue: a movie, or a season's episode in progress (the latest, if several), else its next unwatched, then the rest after it; each entry with its item's other copies to try in turn, the quality's, then its other qualities'. A download on this Mac plays from its file, first (`Playback.downloads`).
* [PlaybackSession.swift](Cinematheque/Shared/PlaybackSession.swift): playing a queue in an `AVQueuePlayer`, streaming by byte ranges. It starts from the copy whose server answers first (`prefer`, by the core's copy racing, racing the queue's later items in the background), and puts an item's next copy in its place when one doesn't load (`loaded`). It starts at the item's position unless it's watched, saves progress every 10 seconds (but not within the first 10, where a resume's seek may not have landed) and where it's paused or closed (so stopping within the first 10 seconds deletes it; on the Mac, the first save reconciles downloads, so a series' next episode comes while this one plays), reloads tiles' progress when it stops, marks each item watched at its end, and goes on to the next. Each player wraps it in its platform's view.
* [FadingIn.swift](Cinematheque/Shared/FadingIn.swift): how playback starts on every platform: the screen fades to black while the session warms up, paused (`PlaybackSession.begin`: the first item loaded, sought to its position, and prerolled); then it plays and its `Curtain` rises: the picture fades in as the sound rises from silence (on a television, after the display has switched to the video's mode, while paused). Leaving lowers it before what follows. Every fade, of picture or sound, takes 0.5 seconds (`Platform.fade`); resuming starts 4 seconds (`Platform.replay`) before where playing was left.
* [TitlePresentation.swift](Cinematheque/Shared/TitlePresentation.swift): how titles and items read on every platform (facts, runtimes, Play and Resume labels from the core's item labels, and Start Over's rewind symbol, before Resume); the quality to play (`QualityChoice`: the best format the player plays, up to its display's resolution); `CoverMarks`, a cover's star (on a list) and check (watched, on green, since tvOS's accent color is white); and `Marks`, the Lists menu and the watched button, which shows its state (Watched or Unwatched) and toggles it when pressed.
* [SetupView.swift](Cinematheque/Shared/SetupView.swift): the first run: pairing by a code this device shows (`OfferedCode`, polling the core until paired; its digits in `CodeBoxes`, a squircle each, in two groups of three, as the field that takes it shows them), the member's device deciding whether it's theirs or someone new's; or creating a library. On the Mac it's a welcome window (`SetupForm`: 520 × 400 points, the scene sized to its content, so fixed while it shows; the app's icon, name, and a line over Create a Library and Join a Library as `Choice` rows, drawn by `ChoiceStyle` as Xcode's welcome window draws its own; joining swaps in the code, with Back); on tvOS, `SetupFlow`.
* [Shelf.swift](Cinematheque/Shared/Shelf.swift): the shelves (Home, those begun and not watched; Movies; Series; Lists, and each list's own; Watched, what's watched through), a tile's context menu marking it watched or unwatched: their names, symbols, tiles (a series' by season), search, counts, and what an empty one says; their orders (`ShelfOrder`, applying the core's places, a series' seasons together, those with no place last; each shelf's default by when last watched for those of what's watched, else by title), which the Mac's View › Sort By chooses per shelf (`SortCommand`, through a focused binding; kept as JSON in `@AppStorage`); and one tile per title, for browsers that show a series as one. The Mac's Watching (stored as `inProgress`) stands in for Home, and only the Mac has Downloaded.
* [CinemathequeApp.swift](Cinematheque/Shared/CinemathequeApp.swift): the app, for every platform: its library, opened from the platform's data directory; the root view, showing the data directory unopened, setting up, or browsing, and, at launch and once set up, naming this device and person, serving, and refreshing; and on macOS, player windows, Settings, and the File menu's New List (⇧⌘N) and Refresh Library (⌘R).
* [Platform.swift](Cinematheque/Shared/Platform.swift): what differs by platform outside the interface: the data directory (on tvOS, its seeds kept in the Keychain), and the device's and person's default names.
* [Launch.swift](Cinematheque/Shared/Launch.swift), in debug builds only: launch options for driving the app unattended (see [AGENTS.md](../AGENTS.md#debugging)).

macOS:

* [Browser+macOS.swift](Cinematheque/macOS/Browser+macOS.swift): `Browser`, the sidebar's shelves beside a grid of covers:
  * **Lists:** Lists' ⊕, and `NewListCommand` in the File menu, make "New List" (numbered if taken) and name it in place. A list is renamed in place (`ListRow`): its name becomes a field; Return keeps what's typed, Escape the name it had, and focus leaving keeps what's typed, but only once the field has had focus, as selecting a new list takes the keys first.
  * **Grid:** covers fit whole (`CoverImage`'s `fit`), dimmed when every copy is on a drive that isn't there (`unavailable`). Each shelf has its own scroll view, as one left scrolled past the end of a shorter shelf drew nothing. Cells are one fixed width (`.adaptive` with equal minimum and maximum), since stretching ones resized every cover at each column change while the inspector animated. The top title is put back only when the column count changes (`onGeometryChange` of `columns`), not at every width an animation passes through, since scrolling at every frame flashed the scroll bar.
  * **Rows:** as cells are fixed, the grid works out every row's place and height before drawing any (`CoverGrid.Rows`: a movie's tile its cover, name, and a line for its year, whether it has one; a season's, its cover and name; a series' name, from AppKit's line heights), and draws only the rows within a screen of what's shown, each at its place, in content of the whole height. A lazy grid guessed at undrawn rows from drawn ones, a series of many seasons as tall as one of few, so the scroll bar's thumb stepped back as it paged and jumped when let go, and paging sped and slowed with the seasons. Paging by the scroll bar's track jumps rather than animating (the app stores `NSScrollAnimationEnabled` off, if unset, as AppKit reads it past registered defaults): with rows and covers arriving mid-animation, SwiftUI set the scroll position from its own record, behind AppKit's, so holding the track pulled it back, up to hundreds of points at a time, and letting go jumped it ahead. The rows on screen are those clear of the toolbar and the status bar; selecting scrolls by offsets, which count from the content's top at rest, below the toolbar, where the visible rectangle's count from under it.
  * **Bars:** `StatusBar` floats over the grid's bottom, a long operation's progress read from `cq_steps` twice a second while one runs; the grid's bottom margin lets its last row clear it. `ProblemBar` shows what went wrong along the bottom of Settings. Neither is ever an alert.
  * **Inspector:** applied outside the split view, as in Apple's WWDC23 example, so it's full height. Its toggle is the app's, declared twice, one shown at a time: in the grid's toolbar, after search, while it's hidden; in the inspector's own (its `.toolbar`), at the end of its section after a flexible `ToolbarSpacer` (macOS 26 and later; before, at its start), while it's shown; so it stays at the window's far right either way. SwiftUI's own toggle came and went between launches, missing in some, so it isn't relied on. The inspector is attached only while shown (`Inspecting`): hidden, its collapsed divider still took the window's last 16 points, over the grid's scroll bar, and dragging the bar there opened it; insetting the bar instead moved it off the window's edge. So View › Show Inspector (⌃⌘I) is the app's too (`InspectorCommand`, through a focused binding), as the system's goes with the inspector.
  * **Toolbar:** search is AppKit's field (`SearchField`, an `NSSearchField` in a toolbar item of the grid's own, 160 points wide; Escape clears it, and Find gives it the keys through `SearchFocus`), since SwiftUI's `searchable` puts search at the window's trailing end, over the inspector while it's shown (`DefaultToolbarItem(kind: .search)` doesn't move it). A shelf's own action goes before it: Downloaded's Show in Finder (the downloads folder) and Watched's Forget Watched… (`eraser`, confirmed first; `Library.forgetWatched` marks each watched tile's items unwatched, an item at a time, then reloads the tiles once). The window is at least 960 points wide (`browsingSize`), so with the sidebar and the inspector shown, the grid's toolbar holds its title, an action, and search: SwiftUI drops a toolbar item that doesn't fit rather than shrinking it, and a minimum on the grid alone squeezed the sidebar instead.
* [InspectorView.swift](Cinematheque/macOS/InspectorView.swift): the selected tile's larger cover; Play or Resume, with Start Over before Resume; the Lists menu and watched mark (borderless); progress meters; metadata; a movie's versions or a season's episodes (season 0 as Specials, each playing with the rest queued), described on demand; and the quality picker (`qualityPicker`, by `QualityChoice.shortNames`) above Play. Downloading (`DownloadControls`): a movie's row (Download with its size, a `DownloadGauge`, a trash button), a season's (the series' Download menu, a gauge, a trash button), and each row's `DownloadMark` and context menu (`DownloadMenuItems`, with `PlaceItems` and `DownloadSection`, also a movie tile's).
* [PlayerView.swift](Cinematheque/macOS/PlayerView.swift): the playback session in AppKit's `AVPlayerView`: `WindowPlayer`, filling the library's window, with Back (Escape), showing while the pointer moves and for 3 seconds after, and back at the queue's end; or `PlayerView`, a window of its own, titled for the item playing, which closing stops. `PlayAction` (the `play` environment value) chooses between them by ⌘. The toolbar is hidden through AppKit (`NSToolbar.isVisible`), since SwiftUI's hiding a window's toolbar hides its window buttons too. `KeyedPlayerView` takes the keyboard (Space, F, M, and the arrows, 10 seconds back and forward) by a key monitor on its window, since AppKit's player view handles the arrows (a frame at a time) in a view of its own; it tracks the pointer itself, as SwiftUI's hover tracking over it keeps AVKit's controls from showing. The title bar's row, fading with the controls as QuickTime Player's does, holds the window buttons, Back, and `NowPlaying`, what's playing, after Back, where macOS puts a window's title.
* [Settings](Cinematheque/macOS/Settings), a file to a pane; a pane listing devices nearby polls for them (`Nearby`); no keys anywhere, and no addresses outside Advanced:

## In detail

How the players look and behave, as built, elaborating [AGENTS.md](../AGENTS.md#apple-players).

### Both

* **Title presentation:** seasons are named in the app (`Tile.seasonName`): "Season 3", "Specials", or a dated series' year alone ("2026", a season of 1000 or more, as the core reads it). Episode names and Play labels are as the core names them; quality pickers give each quality the core's short name, with its full name, as its sources give it, as help. The Lists menu (`ListsMenu`: every list, checked if the title's on it, then New List…; named Lists whatever it's on, so nothing beside it moves) and the watched mark are quieter than what plays (borderless on the Mac, icons alone on the Apple TV). Start Over (`backward.end.fill`, before Resume, as a player's timeline starts at its leading edge) plays what Play would from the beginning, on every platform; it's the one way to start over, since marking something unwatched forgets where you stopped too.
* **Shelves** ([Shelf.swift](Cinematheque/Shared/Shelf.swift), above): a series' shelf counts its episodes too. A tile's context menu has Mark as Watched (unless it is) and Mark as Unwatched (if it's begun or watched): for a season's items, or, on the Apple TV's tiles of a whole series (the Series section's and Search's), for the whole series, with no Lists, as only movies and seasons go on lists.
* **Setup** ([SetupView.swift](Cinematheque/Shared/SetupView.swift) and [SetupFlow+tvOS.swift](Cinematheque/tvOS/SetupFlow+tvOS.swift), above): on the Mac, Create a Library is the default. Neither app shows or takes keys.
* **Playing** ([FadingIn.swift](Cinematheque/Shared/FadingIn.swift) and [PlaybackSession.swift](Cinematheque/Shared/PlaybackSession.swift), above), on every platform: leaving fades to black as the sound falls, saving the position where that fade ends, so resuming replays the 4 seconds before it.
* **Copies:** a download on this Mac plays from its file, first and unraced. Else the stream starts from the copy whose server answers first, among the chosen quality's available copies only, never another quality's (copy racing, `cq_race`, in the core; with one copy, no race). Every copy is asked at once (`HEAD`, 1.5 seconds, or, once one has answered, 250 ms more for a better-placed one, as a NAS waking); one that refused or missed the deadline in the last 10 minutes (as this device notes) is asked last, so a server that's asleep costs a second or so, not a network timeout. The sources' servers' names are looked up once a launch's refresh is done (`cq_race_warm`), since a name's first lookup may outlast a race. When a copy doesn't load (a drive unplugged), the item's other copies follow in turn, the quality's, then its other qualities'.
* **Sharing:** the apps share the library (and the Mac its folders) while they run, serving on the port they got last, so other devices sync with them directly. They sync quietly (not shown as an activity) a minute after they last synced, and whenever they come to the front (as an Apple TV app returns from the home screen, never relaunched). After a change of their person's (pausing or leaving playback, a watched mark, a list), once changes stop for a second and any sync or other long operation under way is done (as it may have begun before the change), they sync with the devices the last sync found (`cq_sync_known`), pushing it to every device at once. When a device pushes its changes to them, they reload at once. For diagnosis, a setting of its own, Show sync activity (off by default), shows the last exchange each way that changed something, in one line: what was received, from which device, what was sent, to which, and when.

### macOS

* **Shelves:** Movies, Series, Watching (what's in progress), Watched (what's watched through, with Forget Watched… in its toolbar), and Downloaded (what this Mac keeps, with Show in Finder in its toolbar), then each list under Lists (its heading's ⊕ making one); no All. The one shown last is shown again at launch (at first, Watching), searchable.
* **Grid:** covers in fixed cells, 148 points wide at any width, so a change in width reflows whole tiles and resizes none; movies 2:3, and each series' seasons square under its name (each season's cover whole, fit and centered, here and in the inspector).
  * **Group by Series:** on the Series shelf, and its search, while View › Group by Series is checked (`GroupCommand`, the setting `groupsSeries`; the grid made anew as it changes, keeping its place by its topmost title), the grid shows a tile per series instead (`Rows.init(series:)`, of `perTitle`'s tiles). Under the series' name, it says how many seasons it has, or, of one, which (but nothing for a first season alone, a miniseries or one cut short, as Firefly, the line kept), so every series' tile reads alike. Its year, if its name has one, is right-aligned on that line (or, if that line's blank, on the name's, an em's space left between them, as `ViewThatFits` measures; the blank line kept, so rows line up), so series of one name, as The Tick (1994) and (2001), are told apart.
  * **Bands:** the selected series (`pointed`) is open unless `collapsed`: its seasons on a band (`Band`, a rounded rectangle tinted with the primary color, its point above the series' column) in a layout row after the series' row, its height known from its seasons' count, so every row's place still is. Opening one keeps it selected, by its key (no season's ID), and the inspector shows it whole (`SeriesInspectorView`). One tile is ringed, the series or a season in its band, as the inspector shows; closing a band whose season is selected selects its series.
  * **Motion:** opening and closing are animated together (`bandMotion`, a quarter second, none under Reduce Motion). The band fades as one (`compositingGroup`, as a fade otherwise applies to each season and the tint apart, the tint showing through them); its seasons' captions, each the version of its name that fits (`ViewThatFits`), have no transition of their own, as they came late as a band opened and went first as it closed (turning animation off within the band, or each tile, instead took them out at once as it closed). The series after it move as their rows' offsets change, and the scrolling goes with them. A band opening as another closes above it comes in from as far off as its series' row moves (`bandEnter`), and one closing as another opens above it goes as far as its own row does (`bandLeave`, drawn a frame ahead, as a view leaving takes its transition from how it was last drawn), so each moves with its row: a view coming or going is drawn where it ends, or was, not moved by its row's offset, even drawn as part of that row (as an overlay, tried, showed).
  * **Layering:** the series' rows are drawn on the grid's ground (`background`, opaque, by `backing`, from the gap above each down), each over those before, so the series after a band slide off it as it opens, showing it from its top down, its foot keeping with them, and back over it as it closes, as the web client's band grows in its page's flow. (Unrolling the band itself stalled midway, on a Mac as in the VM, whether by a custom animation clipping it or by a mask scaled from its top, as fades and offsets, which the window server runs, don't.) The grid's height doesn't change as bands open and close: room is kept at its end for the tallest band (`Rows.init(series:)`'s `most`), so the scroll bar holds still; the tile per series and each series' seasons are made again only when the tiles change (`RowCache`), not as bands open.
  * **Scrolling to a band:** opening a series below another's band, it moves up as that band closes, its own band moving with it, as in the web client's flow (holding it in place by scrolling made the grid jump, as a scroll happens at once and the rows move over time). Once it has, the grid scrolls smoothly (`Viewport.glide`, animating the scroll view's clip view, as `ScrollPosition` scrolls at once even in an animation), just enough to show its band, the series first if both don't fit (a scroll made as the rows moved happened at once, before they did).
  * **Tiles:** a series' tile has no Lists in its context menu, only marking the whole series watched or unwatched, as only movies and seasons go on lists; a series of one season has its season's menu, Lists too. Each tile has a star at its top leading corner if on a list, a watched mark (top trailing) or progress bar, and a download mark (bottom trailing) if this Mac holds any of it. A name cut short has its whole name as help, and only then (`ViewThatFits`, as help says only what can't be seen). A cover replaces its placeholder without a fade, in the same view: `CoverImage` keeps both, showing one, so a cover arriving adds no view (one added as a band opened was drawn where it would end, fading in there, rather than sliding with its band).
* **Keys and scrolling:** the arrow keys move the selection over the covers: left and right in order, up and down a row, into the next section at its nearest column. On the Series shelf they move over the series, each opening as it's reached; Down from the open one goes into its band, to the season beneath it; within the band, Left and Right go out of its ends to the series beside its own, Up out of its first row to the series just above, in its series' row (its own, or another), and Down out of its last to the next row's; Escape closes it. The selection scrolls just enough to show it, and Return plays it, as double-clicking does (a series' season to watch, for a series). The keys are taken as key presses (`onKeyPress`), as the scroll view took the arrows' move commands before `onMoveCommand` saw them, and read the selection as the grid last set or saw it change (`current`), as a key's handler read the binding as it had been a while before. Each shelf returns to its topmost title (the first row clear of the toolbar) when shown again; the grid keeps that title, not an offset, at the top as its width changes and its rows reflow (the inspector opening or closing).
* **Inspector:** for a series selected on the Series shelf, `SeriesInspectorView`: its cover, Play or Resume for the season to watch ("Up next: Season 2" under it), the whole series' watched mark (`markWatched`'s `wholeTitle`), its facts and description, and its seasons, each a button selecting it, with its progress symbol and how many episodes. For any other selected tile: a larger cover; Play or Resume (queued as [Playback.swift](Cinematheque/Shared/Playback.swift) says), filling its row, with the Lists menu and watched mark beside it (labeled where they fit, else icons alone), and Start Over, labeled where it fits, before Resume, as on the Apple TV; a quality picker in a row of its own above Play, so choosing it changes only what's below it (Play, Download's size, and the rows' stand-ins), its label dropped where the inspector's narrow; metadata; and a movie's versions or a season's episodes (Season 0 is Specials), each playable (an episode with the rest of the season after it queued, so the first's plays the season from its start), described on demand.
* **Downloading:** each in one row in which no control appears or disappears, so nothing moves: a gauge keeps its place while hidden, and what doesn't apply is dimmed. A size is orange if what isn't here yet wouldn't fit. Show in Finder (`folder`, icon alone), beside the trash button, selects what of it is on this Mac: the download first (the file that plays), else what's in its folders. If none is, it's Open in Browser (`safari`), opening a server's listing of it, dimmed only while nothing holds it. Control-click lists every place that holds it, with symbols (which macOS's menus show only by `.titleAndIcon`), in sections by what opening them does, each quality highest resolution first, as the picker lists them: Show in Finder (Download, then each quality's folders, "1080p — Movies") and Open in Browser (each quality by server, "720p Very Fast — art › TV Shows", at its folder's listing); an item's context menu lists the same places, flat. Download stays, as a folder may be a share mounted from elsewhere, worth downloading or not, which only a person knows.
  * **A movie's row:** Download, with its size ("Download 4.2 GB": all its files', in the quality picked; of several versions, the one Play plays, by name, "Download Extended 8.1 GB"; a version of parts, all of them; else that file alone), dimmed once it's here or coming. Its context menu lists each quality the version has under a Download heading, by short name with its files' size ("4K — 22 GB"), a warning triangle for one whose files not here yet wouldn't fit (menus can't be colored), then Available, dimmed (the space available for downloads: free, less the floor kept free); choosing one leaves the picker as it is. Then a round gauge of how far it's come while it comes, and a trash button at the row's trailing edge, canceling while it comes and deleting once it's here, its help warning of the only copy.
  * **A season's row:** a Download pop-up of the series' choice, one level, changed only by picking another (Nothing, Next, Next 3, or Next 10, then All, short since its label reads them, as "Download Next 3"; a count chosen elsewhere is listed too); a round gauge, while any of the season's episodes asked for hasn't come, of how far those asked for have; and a trash button at the trailing edge, deleting the season's downloads. Deleting or canceling a download its series' choice asks for sets the choice to Nothing, so it isn't fetched again.

Each choice has its size (all its files') after a dash, and a warning triangle if it wouldn't fit, as the other download menus have them; then, after a divider, the space available for downloads (above the floor kept free), dimmed: a Picker's item made unselectable by `selectionDisabled()` (`disabled()` leaves it selectable there), its tag no choice.
  * **A version's, part's, or episode's row** (one kind of row; a version's name wraps, an episode's stays on one line): its mark, and a context menu like a movie tile's: every place that holds it, flat under Show in Finder and Open in Browser (as Show in Finder's menu has them), the qualities under Download (as the button's menu has them), Delete Download (saying so if it's the only copy), and Cancel Download; then Mark as Watched or Unwatched.
* **Crawling:** while a crawl runs, the grid reloads as it commits (polling `cq_data_version` each second), reading, decoding, and sorting the tiles and sources off the main thread (`reloadApart`), as they're the whole catalog (on the main thread, a crawl of 100,000 files left the Apple TV's main thread idle a tenth of the time); the tiles on screen go to the core to be described first.
* **Playing:** in the library's window, filling it over the browser (which keeps its place), the toolbar hidden and the title bar transparent. Its row, as QuickTime Player's, holds the window buttons; Back (a round button of a chevron alone, the height of their row, glass on macOS 26 and later, as Apple's apps' Back beside a window's buttons), which returns to the library, as Escape and the queue's end do, its black fading away; and what's playing (a movie's name, or a series' with the episode's code and name, "Archer · S1E9 · Job Offer"), as a window's title is on macOS 26 and later: after Back, at the leading edge, in its size and weight, on the window buttons' line, over a faint gradient. The row shows only as the player's controls do, while the pointer moves and for 3 seconds after. With ⌘ held (⌘-click, ⌘-double-click), it plays in a window of its own, titled with what's playing, as many as wanted; player windows aren't restored at launch. Space plays or pauses, F toggles full screen, M mutes, C toggles captions (in the languages preferred, the rest of the queue too; a beep if there are none), and the left and right arrows skip 10 seconds, in an `AVQueuePlayer` in AppKit's `AVPlayerView`. While it plays, the display neither dims nor sleeps (an activity of its own, as AVPlayer's didn't hold).
* **Settings:** four tabs, by what people do, with addresses under Advanced; names are ones everyone in the library sees. Buttons with text have no symbols, as macOS's settings' don't; a symbol is for one that shows nothing else. On launch the app names this Mac and you (the computer's name, the account's first name) if they have no names. Long operations run off the main thread.
* **People:** members by name, with the founder, and you renamable in place; no one's added here, as a device advertising itself proves nothing: people join by code, in Devices.
* **Devices:** your named devices, this Mac among them, each renamable in place and, but for this Mac, removable; sharing the library on the network while the app runs; New Devices, always shown, listing new devices nearby offering to be added, each with six boxes for the code it shows (in two groups of three, as the device shows it), then Yours and Someone New, enabled once the code's in, Yours then drawn as the default and pressed by Return (the box ring gone once the code's whole). Each pairs it, Someone New adding its person; a wrong code shakes the boxes clear, as the login window does. Under Advanced: devices by address (beyond a NAT, say), and Show sync activity.
* **Sources:** Add Folder… and Add Server… (buttons, not a menu; a server's address in a field the sheet's width, ready to type in) in one row at the pane's foot (refreshing is the File menu's), and above them, under Advanced, Look for videos (a pop-up of the library's interval: Manually, Every Hour, Every 3 Hours, Every Day, Every Week). Each source's row ends in Show in Finder (a folder on this Mac) or Open in Browser (a server's listing) and Remove (a minus), as its context menu has them. Folders on this Mac are served at `http://<Mac>.local:<port>/<folder>/` while the app runs and kept in the app's settings; one that isn't there (a drive unplugged, a share unmounted) is shown as unavailable and served empty, so a crawl marks it unavailable. Sources have readable names ("art › Movies › 2160p"). A source's sheet has its quality under Advanced (names to skip are the command-line app's to change), and its unavailable folders, each with when it went and Remove Videos (a minus); devices' downloads aren't listed. If the app must serve on another port, it moves its folders' sources there.
* **Downloads:** the folder (`~/Movies/Cinematheque` unless chosen, as Apple's TV app keeps `~/Movies/TV`), served at `/downloads/`; what it holds, the space free, and of it what's available for downloads ("70 GB free, 50 GB of it available for downloads"), "free" being the disk's and "available" Cinematheque's recommendation; progress while downloading; and the rule: what's downloaded by hand stays until deleted, and a series' watched episodes go as their space is needed.
* **Toolbar:** the sidebar's toggle at the window's far left, then the shelf's title; over the grid, a shelf's action and search; the inspector's toggle at the window's far right whether it's open or not (⌃⌘I), as Xcode's. Refresh Library (⌘R, in the File menu, after New List, ⇧⌘N) syncs, then crawls; with ⌥ held it's Refresh Library Fully (⌘⌥R, SwiftUI's `modifierKeyAlternate`), whose crawl (`cq_crawl_full`) lists every folder afresh, since a folder's time doesn't change as a file in it is retagged in place, so a plain refresh reuses its listing and misses the change. Both show throughout as looking for new videos ("Looking for new videos…", then "Looking in 3 of 6 sources…"). At launch, if there's a library, the app shares it, syncs, names itself if need be, then crawls, syncing before writing anything, so a device whose replica was lost learns its own writes back first.
* **Status bar:** floating over the grid's bottom, so fading moves nothing. At its leading edge, the shelf's counts ("4,000 movies"; "12 of 4,000 movies match …" while searching), or what went wrong; at its trailing edge, what a long operation is doing, with a progress bar, or else, if Show sync activity is on, the last exchange each way that changed something ("Received 3 changes from firefly 1m ago · Sent 12 changes to Den just now", counting operations), unless a problem shows. It fades out 3 seconds after it last changed, unless something is running or wrong, and comes back when the pointer nears it.
* **Tooltips:** short, sentence-style fragments without a period ("Delete download"), saying only what the control and the text around it don't: its name, for one that shows only a symbol; else a warning or state, as "The only copy". Explanations go in the pane's text.
* **Modelessness:** no spontaneous alerts, after the original Macintosh guidelines: like stealing focus, an alert nobody asked for interrupts. An action is confirmed first only if it's hard to undo: removing a source (saying how many videos go, on every device, its files untouched), since only adding it again and looking for its videos anew undoes it; removing someone, leaving the library, and forgetting what's watched; and deleting a download that's the only copy, which nothing undoes. What goes wrong shows in the status bar (and in a bar along the bottom of Settings) in words, never the core's error names, each source by its name ("Looking for new videos failed for art › Movies › 2160p (and 5 more): the server has nothing at that address."), until dismissed, until the next action of its kind (refreshing, changing the library, reading it) succeeds, or until the device gains or leaves a library.

### Apple TV

* **Data directory:** in the caches (the core's default on tvOS), the only place tvOS lets an app keep files, which it may purge; the seeds (`identity`, `user`, `library`) are kept in the Keychain too, and put back at launch, so a purge loses only what syncing and crawling rebuild.
* **Refreshing:** at launch, naming itself (the Apple TV's name) if it has no name, sharing the library (so its progress and lists reach the person's other devices), then syncing with devices found by DNS-SD, then crawling the sources itself.
* **Exchanges:** if Show Sync Activity is on, the last exchange with devices each way that changed something, shown for a few seconds in the corner after each.
* **Home:** `Browser` is one `NavigationStack` whose root is the home page (`HomeView`), every page pushed onto it, so Back retraces them and, at the root, leaves the app, as the system does. There's no tab bar, so nothing above the content takes focus. At the top are the sections' buttons (`Sections`, links by a `Section` value: Movies, Series, Lists, Watched, then Search and Settings as symbols), a focus section across the page's width. Focus starts on the first, where the system starts it, as `defaultFocus` and `prefersDefaultFocus` on Continue Watching's first cover were both passed over at the stack's root. Then come Continue Watching and a row per list (`Row`, each a focus section, so moving down enters the nearest). A list's heading has `SeeAll`, a small button saying See All, how many titles the list holds, and ›, opening `ListPage` (by `ListPageID`); it's centered on the heading, as on its baseline its pill drooped, and the heading's line is a focus section, as a row is (a poster-sized tile first in the row was too large and pushy). A row is a carousel: each cover at the row's height (360 points, a grid's 2:3 cover's), its own width by its shape (`CoverImage`'s `shaped`: the cover's, else its ThumbHash's, else square), its name laid out under it as wide as it (`UnderCover`, a layout sizing the rest by the first, so a long name is cut short rather than widening the cover's slot).
* **Sections:** `SectionPage`, each under its name, as the grid's first line: Movies, Series, Lists, Watched, Search, and Settings. A link's value is typed (`SeriesSeasons`, `ListPageID`, a `Section`, or a `Tile`), as destinations are found by the value's type, not under `AnyHashable`.
  * **Series:** a cover per series, its progress over every season's running time, opening `SeasonsView`: its name; Play or Resume named for the season to watch (`Library.nextSeason`, the first not watched through; "Resume Season 2"), focused first, its details read before it's drawn so it's there to be; the whole series' watched mark (`markWatched`'s `wholeTitle`); then its seasons in square cells, each cover fit whole at the center. A series of one season opens it.
  * **Lists:** every list's row, as Home's. `ListPage` is the whole list as a shelf's grid, its name the grid's first line, aligned with the covers and scrolling with them (a navigation title stayed at the top, inset from them), with Rename…, Share… or Stop Sharing, and Delete List… after the covers, as `PosterGrid`'s footer. The page dismisses itself once its list is gone (deleted here or elsewhere), as it has nothing left to focus to go Back from. Naming, there and by New List, is on the full-screen keyboard at once (`KeyboardField`, unseen, as Settings' names), as an alert's field brought up the keyboard over the alert. New List comes after the last list, as these are rare.
  * **Covers:** six to a row, as tvOS's lockups (borderless buttons, the cover's highlight effect lifting it; its name moved down by hand while focused, as the style moves a title only for an `Image`), with progress and watched marks, and a star if on a list (a series', if any season is). Seasons show everywhere but the Series section and Search, as on the Mac, so lists show what they hold, each named under its series' name, or, among its series' seasons, by its own name alone.
* **Settings:** laid out as tvOS's Settings app lays its out, measured against it in the simulator at the same scale and kept as proportions of the screen.
  * **Layout** (on tvOS's 1920-point screen): the picture 540 points wide, centered at 528 by 506; the explanation 768 wide, low at 940; the list's plates from 1060 to 1840, the left pane behind them; a subpage's title centered at 90.5 (`.title2`, bold, tertiary), drawn by the page, as SwiftUI's navigation title sits lower and pushes the list down. Rows are in the system's text size (`.headline`, larger than a form's own), their text and headings inset 30 points in their plates, as the system's (`listRowInsets`), wider than a form's. The app's icon (`SettingsIcon`, flattened by [draw-icons.swift](draw-icons.swift) from the cinema-red gradient and `film.stack`) is centered in the left half. Under it, small and gray, crossfading, is what the focused row does (or a problem leaving, whatever's focused), in place of footers; it's each row's accessibility hint too, since VoiceOver doesn't reach what's shown only on focus. The list, in the right half, is a `Form` in the grouped style, so its rows, plates, and headings are the system's (each row on a rounded plate of one height, a toggle's state its value; headings small, uppercase, and bold: Names, Library), its rows without symbols.
  * **Values:** every row with a value is a `ValueLabel` (Show Sync Activity too, a button with the toggle trait, its state as its value, as SwiftUI's toggle can't stack), the value on one line, truncated, so rows keep one height. At accessibility text sizes, as the system's, its value goes under its title, rows grow to three lines' height (200 points, as the system's), and the picture shrinks to 316 points wide, centered at 344, the explanation running from under it.
  * **Names:** this Apple TV's name and its person's, each a button row (its title, value, and a chevron, as the system's Name row has, though a keyboard opens) that, pressed, brings up the full-screen keyboard at once, titled with the row's name and holding the name.   * **Library:** Refresh Library, as at launch; Look for New Videos, the library's interval, a row opening a page of its choices, as tvOS's Settings has them (titled at the top; the current one checked and focused first; choosing one sets it and goes back): a button pushing buttons (`navigationDestination`), since a picker's `.navigationLink` style opens an empty list, its row's chevron drawn as the system's (`ValueLabel`: 18 by 32 points, 32 after the value and 36 short of the plate's edge, scaling with the text), as a form's own is smaller and farther from the value; Show Sync Activity; and Leave This Library…, confirmed first (as ending it, with no one else in it), or, on the founder's only device, asking who takes over, once a refresh or sync under way is done, then returning to setup, or saying why it couldn't.

As tvOS's rows have no buttons of their own, pressing a row acts on it: another person or a source asks to confirm removing it (a `confirmationDialog`); another of your devices asks whether to rename it (the same unseen `KeyboardField` as the names) or remove it; and you, the founder, and this Apple TV, explained on focus, do nothing. Adding a device lists those offering nearby (`Nearby`, every 2 seconds, as the Mac's Devices pane); pressing one brings up the keyboard's digits (`.numberPad`) for its code, and adding it goes back to the list, where it now is. Add Server takes an address on the keyboard laid out for one (`.URL`, `http://` typed for you); one that isn't a web address is explained, to type again.
* **Pages:** a movie's, over a blurred backdrop of its cover: Play or Resume (Start Over before Resume), a Quality picker (of one quality, its name as text), and the Lists menu and watched mark, on one row, the picker beside what it plays; then versions, and its description. A season's (`SeasonView`): its cover in its own shape; the series' name and the season's, with the seasons before and after it (`Neighbor`, "‹ Season 6" and "Season 8 ›"; at an end, the chevron alone, dimmed, focus moving to the other there, as a dimmed button kept it; their row a focus section, so moving up from Play reaches them) in the page's top corner, beside the series' name, moving to it in place; Play for the season's next episode, focused first, then its Quality picker, Lists menu, and watched mark, as a movie's; and its episodes under an Episodes heading, described as the season's shown. The quality is the best it plays unless one's chosen: MP4, MOV, or M4V (not MKV or ISO), up to 2160p on a 4K display, else up to 1080p.
* **Playing:** full screen in `AVPlayerViewController`, started once per request (fading the page re-hosts it, so not in a view's task); Play pressed again over the black is ignored until the player's on screen. AVFoundation and AVKit are loaded as the shelves first show. The page fades to black while the stream warms up, the session made once the fade's done; then the display switches to the video's frame rate and range (asked of the window by the app, if Match Content is on), blanking the screen; then UIKit presents the player over the black ([TVPlayer.swift](Cinematheque/tvOS/TVPlayer.swift)), unanimated and ready, so it shows no spinner of its own (until then, UIKit's large white spinner shows on the black, at the screen's center, as the player's would); then its picture fades in as its sound rises, once it's playing, not merely asked to (surround passed through, encoded, to a receiver can't ramp, and comes at once). Its remote skips and scrubs as the system's player does, and its info panel (and Now Playing) shows each item's title, description, and cover.
* **Leaving:** Menu (Back) fades it to black as its sound falls; then, its controls hidden, the display is given its own mode back, and while that switch runs (some 3 seconds, the screen blank), it's stopped and dismissed over the black page, which fades back in once the switch is done. Going to the background (the TV button), it pauses, silent, and comes back paused (AVKit's own resume held off), its sound rising when it's played.

## Checking the interface

The Apple TV player runs in the tvOS simulator (an Apple TV 4K, 3rd generation, made for testing with `simctl create`), which reaches the LAN from the host. Install the debug build with `simctl install`, launch it with launch options prefixed `SIMCTL_CHILD_` (e.g., `SIMCTL_CHILD_CINEMATHEQUE_TAB=movies xcrun simctl launch DEVICE com.rbrian.cinematheque`), and capture it with `simctl io DEVICE screenshot`. The launch options reach states the remote would take many presses to. An agent drives its remote through Xcode's MCP tools: `DeviceInteractionStartSession` (with the simulator's UDID; its advice to load a `device-interaction` skill in a subagent can be skipped); then `DeviceInteractionSynthesize` with `r up`, `r down`, `r left`, `r right`, `r select`, or `r menu` (Back), or with no command, to capture; and `DeviceInteractionEndSession` when done. Each call returns a screenshot and a UI hierarchy, which marks the focused element `Focused`: count presses by it, as focus skips dimmed rows, and trust it over a screenshot taken mid-transition. By hand, it runs in Device Hub, Xcode's simulator app (in `Xcode.app/Contents/Applications`).

Screenshots come from a macOS VM, run by terrarium from the `macos-27.2-quiet` layer, whose screen it captures without screen-recording permission on the host. Put the debug build's app in the guest at `~/Cinematheque.app`, with media and the [command-line app](../cli/README.md) serving it on the guest's loopback (`serve --media`), then open the app, to set up from scratch, or with a data directory in place and launch options, e.g., `open --env CINEMATHEQUE_SELECT=t/m/all-systems-red/2017 ~/Cinematheque.app`. In a tight loop of changes, keep the VM running and replace only the app (quit it, copy the new build in, reopen it), keeping the guest's media server and data directory; stop the VM when work moves away from the interface. Drawing the window from within the app instead (`cacheDisplay`, or rendering its layers) misses macOS 26's floating sidebar.

## Findings

* Played from a Caddy server on a NAS, over Wi-Fi: HandBrake's `.m4v` files open in seconds, and seek, with their audio and subtitle tracks.
* Of 14 HandBrake files on a NAS, every one carried a JPEG cover (2:3 posters for movies, 667×1000; squares for TV, 800×800) and a description.
* A tile with both a double-click and a single-click gesture delays selection by the double-click interval; selecting is a plain tap, and playing a simultaneous double tap.
* SwiftUI's `VideoPlayer` failed to load when the app ran unbundled ("failed to demangle superclass of VideoPlayerView"); AppKit's `AVPlayerView` works either way.
