# Apple players

The players for Apple devices, in SwiftUI, on the [core](../core/README.md) through its C interface:

* **macOS** (macOS 15 or later): it sets up and manages a library, browses it by cover art, and plays copies straight from their sources, keeping the person's progress and watchlist. It opens this device's home (`CINEMATHEQUE_HOME`, or the default), which it shares with the [device](../cli/README.md).
* **Apple TV** (tvOS 18 or later): it pairs as a person's device or joins their library, syncs with devices and crawls the sources itself, browses by cover art with the remote, and plays full screen, keeping progress by the same rules.

## Building

Open [Cinematheque.xcodeproj](Cinematheque.xcodeproj) in Xcode and run the Cinematheque scheme on My Mac, an Apple TV, or a tvOS simulator; Product › Show Build Folder in Finder finds the app in DerivedData. Or, from the command line:

```sh
xcodebuild -scheme Cinematheque -configuration Release build
open "$(xcodebuild -scheme Cinematheque -configuration Release \
  -showBuildSettings | sed -n 's/^ *BUILT_PRODUCTS_DIR = //p')/Cinematheque.app"
xcodebuild -scheme Cinematheque \
  -destination 'generic/platform=tvOS Simulator' build
```

The project is in Xcode 27's format ([project.xcproj](Cinematheque.xcodeproj/project.xcproj), readable JSON, converted with `xcodebuild -convert-project "Xcode Project"`), so it needs Xcode 27 or later. It has one multiplatform app target, Cinematheque, for macOS, tvOS, and tvOS's simulator; settings that differ by platform are conditioned on the SDK (e.g., `[sdk=macosx*]`):
* **Sources:** the [Cinematheque](Cinematheque) folder, which Xcode keeps in sync, so new files need no project edits: [Shared](Cinematheque/Shared) for both platforms, and [macOS](Cinematheque/macOS) and [tvOS](Cinematheque/tvOS), each file of which is wrapped in `#if os(macOS)` or `#if os(tvOS)`. A view each platform has its own of shares its type's name (`Browser`), so shared code names it once; its files are suffixed by platform (`Browser+tvOS.swift`), since a target can't compile two files of one name.
* **Core:** the build phase runs [build-core.zsh](build-core.zsh), which builds it with Zig, ReleaseSafe (from `/opt/homebrew/bin` or `/usr/local/bin`) for the platform (macOS, tvOS, or its simulator, with the SDK as sysroot) and each architecture being built, so Release builds are universal, and links each into one object exporting only the C interface (`ld -r -exported_symbol '_cq_*'`), since the compiler runtime Zig bundles (which the core needs for 128-bit floats) would otherwise clash with Xcode's. Swift imports it as `CCinematheque`, by the [module map](../core/include/module.modulemap) beside its header.
* **Bundle:** [Info.plist](Cinematheque/Info.plist), merged into the generated one, allows plain HTTP and Bonjour (`_cinematheque._tcp`) on the local network, where sources and devices are, and, preprocessed (`#if TVOS`, defined for tvOS's SDKs), declares the `cinematheque://` links the Top Shelf opens on tvOS only; [Assets.xcassets](Cinematheque/Assets.xcassets) holds placeholder icons, drawn by [draw-icons.swift](draw-icons.swift) (a cinema-red gradient and the `film.stack` symbol): the Mac's, on its icon grid (a rounded square 824 of 1,024 across, since macOS sets a full-bleed square on a gray plate), and the Apple TV's brand assets (its icon in two layers, for parallax, the Top Shelf, and Settings' picture, `SettingsIcon`). A compiled catalog matters beyond looks: without one, tvOS's search keyboard faults looking for it (CoreUI's "unable to find a bundle").
* **Scheme:** shared, with `CINEMATHEQUE_DATA` ready, disabled, for running on another library.
* **Settings:** Xcode 27.2's recommended ones (its macOS app template's), but for four, on purpose: script sandboxing is off for the core's build phase, which reads `../core` and Zig's cache; there's no App Sandbox, since the app shares this device's data directory in `~/Library/Application Support`; the hardened runtime waits for signing for distribution; and the app runs on macOS 15 or later. Swift code is isolated to the main actor by default, with approachable concurrency; what crosses threads (the core's handle, decoded images) is marked `nonisolated`.
* **Signing:** on the Mac, ad hoc; on tvOS, automatic, so the simulator needs no team, and an Apple TV needs `DEVELOPMENT_TEAM` for tvOS. A developer's own settings, such as `DEVELOPMENT_TEAM`, go in `Local.xcconfig` beside [Signing.xcconfig](Signing.xcconfig), which includes it if present; Git ignores it, so they stay out of commits.

## Sources

Shared:

* [Library.swift](Cinematheque/Shared/Library.swift): the library through the C interface (its state, setting up, and calling the core), its parts in extensions by area: [Library+People.swift](Cinematheque/Shared/Library+People.swift) (pairing, names, and devices), [Library+Sources.swift](Cinematheque/Shared/Library+Sources.swift) (sources, folders on this Mac, serving, and refreshing), [Library+Downloads.swift](Cinematheque/Shared/Library+Downloads.swift) (the Mac's), [Library+Sync.swift](Cinematheque/Shared/Library+Sync.swift) (keeping in sync, and saying so), and [Library+Progress.swift](Cinematheque/Shared/Library+Progress.swift) (this person's); [Models.swift](Cinematheque/Shared/Models.swift) holds the JSON it decodes (status, tiles, a title's details, sources, members). It decodes JSON, and running long operations (crawling, syncing, describing) off the main thread, reloading as they commit. What goes wrong becomes `problem`, a sentence (a long operation's first failure by its server's name, and how many more), with its kind, so only a success of the same kind clears it.
* [ArtCache.swift](Cinematheque/Shared/ArtCache.swift): covers fetched by range request, scaled with ImageIO off the main thread (480 pixels for tiles, 1,200 for larger covers), and kept in memory and on disk (the app's caches, `com.rbrian.cinematheque/covers`); until one loads, its placeholder, rendered by the core from its ThumbHash and scaled up, or without one, a color of its own with its title. A cover replaces its placeholder at once (a fade, tried at 3, 0.3, and 0.1 seconds, wasn't worth it); one in memory shows from the start, so scrolling back shows no placeholder.
* [Playback.swift](Cinematheque/Shared/Playback.swift): what to play (`PlayRequest`), and the queue: a movie, or a season's episode in progress (the latest, if several), else its next unwatched, and the rest after it; each entry with its item's other copies, the quality's then its other qualities', to try in turn. A download on this Mac plays from its file, first (`Playback.downloads`).
* [PlaybackSession.swift](Cinematheque/Shared/PlaybackSession.swift): playing a queue in an `AVQueuePlayer`, streaming by byte ranges, starting from the copy whose server answers first (`prefer`, by the core's copy racing, the queue's later items in the background), and putting an item's next copy in its place when one doesn't load (`loaded`), saving the progress every 10 seconds (but not within the first 10, where a resume's seek may not have landed) and where it's paused or closed (so stopping within the first 10 seconds deletes it), reloading tiles' progress when it stops, and at each item's end, marking it watched; each player wraps it in its platform's view.
* [FadingIn.swift](Cinematheque/Shared/FadingIn.swift): how playback starts on every platform: the screen fades to black (0.5 seconds) while the session warms up, paused (`PlaybackSession.begin`: the first item loaded, sought to its position, and prerolled), then it plays and its `Curtain` rises: the picture fades in as the sound rises from silence (on a television, after the display has switched to the video's mode, while paused). Leaving lowers it before what follows. Every fade, of picture or sound, takes 0.5 seconds (`Platform.fade`); resuming starts 4 seconds (`Platform.replay`) before where playing was left.
* [TitlePresentation.swift](Cinematheque/Shared/TitlePresentation.swift): how titles and items read on every platform (facts, runtimes, Play and Resume labels from the core's item labels, and Start Over's rewind symbol, before Resume), the quality to play (`QualityChoice`: the best format the player plays, up to its display's resolution), `CoverMarks`, a cover's star (on the watchlist) and check (watched, on green, since tvOS's accent color is white), and `Marks`, the watchlist and watched buttons, the latter showing its state (Watched or Unwatched), which pressing toggles.
* [SetupView.swift](Cinematheque/Shared/SetupView.swift): the first run: pairing by a code this device shows (`OfferedCode`, polling the core until paired, its digits in `CodeBoxes`, a squircle each in two groups of three, as the field that takes it shows them), the member's device deciding whether it's theirs or someone new's, or creating a library: on the Mac, a welcome window (`SetupForm`: 520 × 400 points, the scene sized to its content, so fixed while it shows; the app's icon, name, and a line over Create a Library and Join a Library as `Choice` rows, drawn by `ChoiceStyle` as Xcode's welcome window draws its own; joining swaps in the code, with Back), and on tvOS as `SetupFlow`.
* [Shelf.swift](Cinematheque/Shared/Shelf.swift): the shelves (Home, those begun and not watched; Movies; Series; Watchlist; Watched, what's watched through; a tile's context menu marks it watched or unwatched): their names, symbols, tiles (a series' by season), search, counts, and what an empty one says; and one tile per title, for browsers that show a series as one. The Mac's In Progress stands in for Home, and its Downloaded is its only.
* [CinemathequeApp.swift](Cinematheque/Shared/CinemathequeApp.swift): the app, for both platforms: its library, opened from the platform's home; the root view, showing no home, setting up, or browsing, and at launch and once set up, naming this device and person, serving, and refreshing; and on macOS, player windows, Settings, and Refresh Library (⌘R), which syncs, then crawls.
* [Platform.swift](Cinematheque/Shared/Platform.swift): what differs by platform outside the interface: the home (on tvOS, with its seeds kept in the Keychain), and the device's and person's default names.
* [Launch.swift](Cinematheque/Shared/Launch.swift), in debug builds only: launch options for driving the app unattended (see [AGENTS.md](../AGENTS.md)).

macOS:

* [Browser+macOS.swift](Cinematheque/macOS/Browser+macOS.swift): `Browser`: shelves (Movies, Series, Watchlist, In Progress, Watched, Downloaded) beside a lazy grid of covers in fixed cells, movies 2:3 and seasons square under their series (covers fit whole, `CoverImage`'s `fit`), with watched marks and progress bars, dimmed when every copy is on a drive that isn't there (`unavailable`); the tiles in view go to the core to be described first while a crawl runs. Each shelf has its own scroll view (one left scrolled past the end of a shorter shelf drew nothing), which returns to the shelf's topmost title, and keeps it at the top when the grid's width changes, as when the inspector opens or closes. Cells are one fixed width (`.adaptive` with equal minimum and maximum), since stretching ones resized every cover at each column change while the inspector animated; and the top title is put back only when the column count changes (`onGeometryChange` of `columns`), since scrolling at every frame flashed the scroll bar. Tiles count as visible once half on screen (`onScrollVisibilityChange`), and leave on disappearing too, since a lazy grid drops a tile it scrolls far past without saying so. `StatusBar` floats over the bottom of the grid: counts or what went wrong, and a long operation's progress (`cq_steps`, read twice a second while one runs), fading 3 seconds after it last changed unless something is running or wrong, and returning when the pointer nears it; the grid's bottom margin lets its last row clear it. `ProblemBar` shows what went wrong along the bottom of Settings. Neither is ever an alert. The toolbar holds the inspector's toggle (⌥⌘I) and, last, search: SwiftUI pins its toolbar search to the trailing edge, and the guidelines put both at the trailing edge without ordering them, so the toggle goes just before search, as in Photos (a custom field could put the toggle last, but would lose the native one's behavior).
* [InspectorView.swift](Cinematheque/macOS/InspectorView.swift): the selected tile's larger cover, Play or Resume (a season from its episode in progress, else its next unwatched, the rest queued), Start Over before Resume, the watchlist and watched marks (borderless), progress meters, metadata, and a movie's versions or a season's episodes (season 0 as Specials, each playing with the rest queued), described on demand, the quality picker (`qualityPicker`, by `QualityChoice.shortNames`) above Play. Downloading (`DownloadControls`): a movie's row (Download with its size, a `DownloadGauge`, a trash button), a season's (the series' Download menu, a gauge, a trash button), and each row's `DownloadMark` and context menu (`DownloadMenuItems`, with `PlaceItems` and `DownloadSection`, also a movie tile's).
* [TopShelfPublisher.swift](Cinematheque/tvOS/TopShelfPublisher.swift): what the Top Shelf shows, Home's two rows, written to the app group's container as `TopShelf/content.json` and a JPEG per cover (named by its location's hash, those no longer listed deleted; a title without one, or whose cover doesn't load, gets its placeholder, rendered from `CoverImage`, so the Top Shelf shows no dots), cleared on leaving the library, two seconds after the library last changed, telling tvOS only when it differs; and the `cinematheque://title?tile=…` links its items open, on Home once the library has the title.
* [TopShelf/ContentProvider.swift](TopShelf/ContentProvider.swift): the Top Shelf extension, its own target, embedded in the app on tvOS only (its dependency and embedding filtered to `tvos` in `project.xcproj`): it reads that file into sectioned content, posters for movies and squares for seasons, each item's display and play actions its link. The app and it share the app group by their entitlements files ([Cinematheque.entitlements](Cinematheque.entitlements), tvOS only, and [TopShelf.entitlements](TopShelf.entitlements)).
* [PlayerView.swift](Cinematheque/macOS/PlayerView.swift): the playback session in AppKit's `AVPlayerView`: `WindowPlayer`, filling the library's window, with Back (Escape), showing while the pointer moves and for 3 seconds after, and back at the queue's end; or `PlayerView`, a window of its own, titled for the item playing, which closing stops. `PlayAction` (the `play` environment value) chooses between them by ⌘. The toolbar is hidden through AppKit (`NSToolbar.isVisible`), since SwiftUI's hiding a window's toolbar hides its window buttons too. `KeyedPlayerView` takes the keyboard (Space, F, M, and the arrows, 10 seconds back and forward) by a key monitor on its window, since AppKit's player view handles the arrows (a frame at a time) in a view of its own, and tracks the pointer itself: SwiftUI's hover tracking over it keeps AVKit's controls from showing. In the title bar's row, fading with the controls as QuickTime Player's does: the window buttons, Back, and `NowPlaying`, what's playing, after Back, where macOS puts a window's title.
* [Settings](Cinematheque/macOS/Settings), a file to a pane, each pane listing devices nearby polling for them (`Nearby`), no keys anywhere, and no addresses outside Advanced:
  * [ManageView.swift](Cinematheque/macOS/Settings/ManageView.swift): the four panes' tabs, and what they share (`RemoveButton`, `Footer`, `Looking`, `Nearby`).
  * [PeoplePane.swift](Cinematheque/macOS/Settings/PeoplePane.swift): members by name, you renamable in place (`MemberRow`), and those waiting to join.
  * [DevicesPane.swift](Cinematheque/macOS/Settings/DevicesPane.swift): your devices, each renamable in place (this Mac's name re-advertised) and, but for this Mac, removable (`DeviceRow`); sharing; New Devices; and, under Advanced, devices by address.
  * [PairRow.swift](Cinematheque/macOS/Settings/PairRow.swift): a new device offering to be added, paired by the code it shows, then Yours or Someone New (enabled once the code's in) (typed into `CodeField`: `CodeBoxes`, showing the code's length before it's typed, over an invisible field that takes focus, typing, and pasting, digits alone; a wrong code shakes it clear (`Shake`), focused again) and moved, animated, into Your Devices or People.
  * [SourcesPane.swift](Cinematheque/macOS/Settings/SourcesPane.swift): folders on this Mac, chosen with SwiftUI's file importer, as the downloads folder is, and served while the app runs, those not there shown as unavailable and served once back, and servers, each added by a button of its own (Add Folder… and Add Server…, whose `SourceSheet` takes a server's address as Finder's Connect to Server does); Look for videos and Refresh Library; a server's unavailable folders, listed in its sheet, each with Remove Videos.
  * [DownloadsPane.swift](Cinematheque/macOS/Settings/DownloadsPane.swift): the folder, what it holds, and the rule for what goes.

Apple TV:

* [Keys.swift](Cinematheque/tvOS/Keys.swift): the data directory's seeds kept in the Keychain, since tvOS may purge the caches that hold it.
* [SetupFlow+tvOS.swift](Cinematheque/tvOS/SetupFlow+tvOS.swift): setting up as tvOS apps do: the app's name over two large choices, each step a screen of its own; joining a library shows a pairing code (`PairingStep`).
* [Browser+tvOS.swift](Cinematheque/tvOS/Browser+tvOS.swift): `Browser`: the tab bar, Home's rows, the poster grid, search, and what a refresh is doing.
* [SettingsView.swift](Cinematheque/tvOS/SettingsView.swift): Settings: the Apple TV's name and its person's, Refresh Library, and Leave This Library…, with its confirmation and, for the founder's only device, its choice of who takes over.
* [TitleViews.swift](Cinematheque/tvOS/TitleViews.swift): a movie's page and a series', with their marks and episodes; seasons' covers fit whole in their squares (`CoverImage`'s `fit`).
* [TVPlayer.swift](Cinematheque/tvOS/TVPlayer.swift): the playback session full screen in `AVPlayerViewController`, with titles and descriptions for its info panel; presented by UIKit over whatever's frontmost, not by SwiftUI's `fullScreenCover`, since AVKit adds views of its own (snapshots, as its controls animate) beside the player's, which SwiftUI's hosting view doesn't take; presented first, black, then given its curtain (a black view in its `contentOverlayView`, over the picture and under the controls) and the session, since its views made before it's in a window have no scene; detached before it's dismissed. Each item's metadata carries the cover (`commonIdentifierArtwork`), which Now Playing asks for. Playback logs its start's steps and their times (`Playing`, then `Starting #n: raced copies…, loaded…, sought…, prerolled…`, and `matched the display`) under `com.rbrian.cinematheque`, `playback`, to tell where a slow start goes. The shared scheme has `CA_DEBUG_TRANSACTIONS`, off, to log where Core Animation is used off the main thread. While the app isn't active, the sync loop does nothing, so nothing redraws as the system snapshots the app going to the background.

## In detail

How the players look and behave, as built, elaborating [AGENTS.md](../AGENTS.md#apple-players).

### Both

* **Structure:** one `App` and root view (its data directory unopened, setting up, or browsing; at launch and once set up, naming, sharing, and refreshing), over a shared model, cover cache, playback session, title presentation, shelves, setup, and debug launch options; each platform's `Browser` and the rest apart (`#if os(...)`), and what else differs (the data directory, default names) in `Platform`. One Xcode target (Xcode 27's `project.xcproj` format), whose build phase builds the core for the platform and each architecture and links it into one object exporting only the C interface, so the compiler runtime Zig bundles can't clash with Xcode's.
* **Title presentation:** facts, runtimes, episode names and Play labels (as the core names them), the quality to play (its pickers giving each the core's short name, the full name, as its sources give it, as help), and the watchlist and watched marks, quieter than what plays (borderless on the Mac, icons alone on the Apple TV), the watched one showing its state (Watched or Unwatched), which pressing toggles. Start Over (`backward.end.fill`, before Resume, as a player's timeline starts at its leading edge) plays what Play would from the beginning, on every platform; it's the one way to start over, since marking something unwatched forgets where you stopped too.
* **Shelves:** Home, Movies, Series, Watchlist, and Watched (what's watched through), with their tiles, search, counts (a series' shelf counts its episodes too), and empty text. A tile's context menu has Mark as Watched (unless it is) and Mark as Unwatched (if it's begun or watched): a season's items on the Mac, a whole series' on the Apple TV, which shows one tile per series. The Mac's sidebar shows all but Home, with In Progress (Home's) in its place.
* **Setup** (`SetupView`): joining a library by a code this device shows (`OfferedCode`), the member's device deciding whether it's theirs or someone new's, or creating a library; a code shows a digit to a box, in two groups of three, as it's typed on the other device. On the Mac, a welcome window: Create a Library (the default) and Join a Library, which shows its code in the same window. On the Apple TV, tvOS-style steps: the app's name over two large choices (Create a Library; Join a Library, a screen showing its code). Neither app shows or takes keys.
* **Playing** (`FadingIn`), on every platform: fading to black while the stream warms up, paused (loaded, sought to its position, less 4 seconds when resuming, and prerolled), then playing and fading to the picture as its sound rises from silence; when left, fading to black as its sound falls, its position saved where that fade ends, so resuming replays the 4 seconds before it. A curtain (`Curtain`) covers both, each fade 0.5 seconds (`Platform.fade`). It starts at the position unless watched, saves it every 10 seconds past the first 10 and where it's paused or left (on the Mac, the first save reconciles downloads, so a series' next episode comes while this one plays), marks an item watched at its end, and goes on to the next.
* **Copies:** a download on this Mac plays from its file, first and unraced. Else the stream is first from the copy whose server answers first, among the chosen quality's available copies only, never another quality (copy racing, `cq_race`, in the core; with one copy, none): each copy's asked at once (`HEAD`, 1.5 seconds, or once one has answered, 250 ms more for a better-placed one, as a NAS waking), one that refused or didn't answer by the deadline in the last 10 minutes (as this device notes) asked last, so a device that's asleep costs a second or so, not a network timeout. The sources' servers' names are looked up once a launch's refresh is done (`cq_race_warm`), since a name's first lookup may outlast a race. When a copy doesn't load (a drive unplugged), the item's other copies follow in turn, the quality's, then its other qualities'.
* **Sharing:** the apps share the library (and the Mac its folders) while they run, serving on the port they got last, so other devices sync with them directly. They sync quietly (not shown as an activity) a minute after they last synced, and whenever they come to the front (as an Apple TV app returns from the home screen, never relaunched). After a change of their person's (pausing or leaving playback, a watched mark, the watchlist), once changes stop for a second (and once any sync or other long operation under way is done, as it may have begun before the change), they sync with the devices the last sync found (`cq_sync_known`), pushing it to every device at once; when a device pushes its changes to them, they reload at once. For diagnosis, each can show the last exchange each way that changed something, in one line (what it received, from which device, and what it sent, to which device, and when), behind a setting of its own, Show sync activity, off by default.
* **Project:** Xcode's recommended settings but for script sandboxing (the core's build phase), the App Sandbox (the data directory it shares with the command-line app), the hardened runtime (until signing for distribution), and its macOS 15 minimum; a developer's signing settings stay in an ignored `Local.xcconfig`. The bundle's `Info.plist` allows plain HTTP and Bonjour on the local network.

### macOS

* **Shelves:** Movies, Series, Watchlist, In Progress, Watched (what's watched through), and Downloaded (what this Mac keeps); no All. The one shown last is shown again at launch (at first, In Progress), searchable.
* **Grid:** covers in fixed cells (148 points wide at any width, so a change in width reflows whole tiles and resizes none), movies 2:3 and each series' seasons square under its name (each season's cover whole, fit and centered, here and in the inspector). Each has a star at its top leading corner if on the watchlist, a watched mark (top trailing) or progress bar, and a download mark (bottom trailing) if this Mac holds any of it. A cover shows its placeholder until loaded (without one, a color with its title), then replaces it at once, without a fade; covers are fetched by range request, scaled with ImageIO off the main thread, and cached in memory and in the app's caches.
* **Keys and scrolling:** the arrow keys move the selection over the covers (left and right in order, up and down a row, into the next section at its nearest column), scrolling just enough to show it, and Return plays it, as double-clicking does. Each shelf has its own scroll view, and returns to its topmost title (the first at least half on screen) when shown again; the grid keeps that title, not an offset, at the top as its width changes and its rows reflow (the inspector opening or closing), putting it back only when the columns change, not at every width an animation passes through.
* **Inspector:** for the selected tile, a larger cover, Play or Resume (a movie, or a season's episode in progress, the latest if several, else its next unwatched, with the rest of the season queued), filling its row, with the watchlist and watched marks beside it (labeled where they fit, else icons alone), a quality picker in a row of its own above Play (so choosing it changes only what's below it: Play, Download's size, and the rows' stand-ins; its label dropped where the inspector's narrow), metadata, and a movie's versions or a season's episodes (Season 0 is Specials), each playable (an episode with the rest of the season after it queued, so the first's plays the season from its start), described on demand. Start Over, labeled where it fits, is before Resume, as on the Apple TV.
* **Downloading:** each in one row in which no control appears or disappears, so nothing moves: a gauge keeps its place while hidden, and what doesn't apply is dimmed. A size is orange if what isn't here yet wouldn't fit. Show in Finder (`folder`, icon alone) beside the trash button selects what of it is on this Mac, the download first (the file that plays), else in its folders; if none is, it's Open in Browser (`safari`), opening a server's listing of it, and dimmed only while nothing holds it. Control-click lists every place that holds it, with symbols (which macOS's menus show only by `.titleAndIcon`), in sections by what opening them does, each quality highest resolution first, as the picker lists them: Show in Finder (Download, then each quality's folders, "1080p — Movies") and Open in Browser (each quality by server, "720p Very Fast — art › TV Shows", at its folder's listing), as does Show Files in an item's context menu; Download stays, as a folder may be a share mounted from elsewhere, worth downloading or not, which only a person knows.
  * **A movie's row:** Download, with its size ("Download 4.2 GB", all its files', in the quality picked; of several versions, the one Play plays, by name, "Download Extended 8.1 GB", a version of parts all of them, else that file alone), dimmed once it's here or coming, its context menu each quality the version has under a Download heading, by short name with its files' size ("4K — 22 GB"), a warning triangle for one that wouldn't fit (menus can't be colored), then Free Space dimmed, the picker left as it is; a round gauge of how far it's come while it comes; and a trash button at the row's trailing edge, canceling while it comes, deleting once it's here, its help warning of the only copy.
  * **A season's row:** a Download pop-up of the series' choice, one level, changed only by picking another (Nothing, Next, Next 3, or Next 10, then All, short since its label reads them, as "Download Next 3"; a count chosen elsewhere is listed too); a round gauge while any of the season's episodes asked for hasn't come, of how far those asked for have; and a trash button at the trailing edge, deleting the season's downloads. Deleting or canceling a download its series' choice asks for sets the choice to Nothing, so it isn't fetched again.
  * **Its menu:** a SwiftUI pop-up, so the choice opens under the pointer: each choice with its size (all its files') after a dash, as the other download menus have it, a warning triangle for one that wouldn't fit (menus can't be colored); the space downloads may take (above the floor kept free) in its help, as a pop-up's items are all choices. Regular size, as the Quality picker is, so the button's text matches its menu's.
  * **A version's, part's, or episode's row** (one kind of row, a version's name wrapping, an episode's on one line): its mark, and a context menu, as a movie tile's has: every place that holds it, flat under Show in Finder and Open in Browser (as Show in Finder's menu), the qualities under Download (as the button's), Delete Download (saying so if it's the only copy), and Cancel Download; then Mark as Watched or Unwatched.
* **Crawling:** while a crawl runs, the grid reloads as it commits (polling `cq_data_version` each second), and the tiles on screen are described first.
* **Playing:** in the library's window, filling it over the browser (which keeps its place), with the toolbar hidden and the title bar transparent, its row (as QuickTime Player's) holding the window buttons, Back (or Escape, or the queue's end) returning to the library, its black fading away to it, and what's playing (a movie's name, or a series' with the episode's code and name, "Archer · S1E9 · Job Offer"), as a window's title is on macOS 26 and later: after Back, at the leading edge, in its size and weight, on the window buttons' line, over a faint gradient, the row showing only as the player's controls do, while the pointer moves and for 3 seconds after. With ⌘ held (⌘-click, ⌘-double-click), in a window of its own, titled with what's playing, as many as wanted; player windows aren't restored at launch. Space plays or pauses, F toggles full screen, M mutes, C toggles captions (in the languages preferred, the rest of the queue too; a beep if there are none), and the left and right arrows skip 10 seconds, in an `AVQueuePlayer` in AppKit's `AVPlayerView`; while it plays, the display neither dims nor sleeps (an activity of its own, as AVPlayer's didn't hold).
* **Settings,** by what people do, with addresses under Advanced, in four tabs; names are ones everyone in the library sees. Its buttons with text have no symbols, as macOS's settings' don't; a symbol is for one that shows nothing else. On launch the app names this Mac and you (the computer's name, the account's first name) if they have no names. Long operations run off the main thread.
* **People:** members by name, with the founder, and you renamable in place; no one's added here, as a device advertising itself proves nothing: people join by code, in Devices.
* **Devices:** your named devices, this Mac among them, each renamable in place and, but for this Mac, removable; sharing the library on the network while the app runs; New Devices, always shown, listing new devices nearby offering to be added, each with six boxes for the code it shows (in two groups of three, as the device shows it; pasting works, and only digits go in), then Yours and Someone New, enabled once the code's in, Yours then drawn as the default and pressed by Return (the box ring gone once the code's whole), each pairing it (Someone New adding its person; a wrong code shakes the boxes clear, as the login window does) and moving it, animated, into Your Devices (or People); under Advanced, devices by address (beyond a NAT, say), and Show sync activity.

Folders on this Mac are served at `http://<Mac>.local:<port>/<folder>/` while the app runs and kept in the app's settings; one that isn't there (a drive unplugged, a share unmounted) is shown as unavailable and served empty, so a crawl marks it unavailable. Sources have readable names ("art › Movies › 2160p"); a source's quality is under Advanced in its sheet (names to skip are the command-line app's to change), with its unavailable folders, each with when it went and Remove Videos (a minus); devices' downloads aren't listed. If the app must serve on another port, it moves its folders' sources there.
* **Downloads:** the folder (`~/Movies/Cinematheque` unless chosen, as Apple's TV app keeps `~/Movies/TV`), served at `/downloads/`; what it holds and the space free; progress while downloading; and the rule: what's downloaded by hand stays until deleted, a series' watched episodes go as their space is needed.
* **Toolbar:** the sidebar's toggle and the shelf's title at the leading edge; the inspector's toggle (⌥⌘I) and search at the trailing. Refresh Library (⌘R, in the View menu) syncs, then crawls, shown throughout as looking for new videos ("Looking for new videos…", then "Looking in 3 of 6 sources…"). At launch, if there's a library, the app shares it, syncs, names itself if need be, then crawls, syncing before writing anything, so a device whose replica was lost learns its own writes back first.
* **Status bar:** along the bottom of the grid, floating over it, so fading moves nothing: the shelf's counts ("4,000 movies"; "12 of 4,000 movies match …" while searching), or what went wrong, at the leading edge; at the trailing, what a long operation is doing, with a progress bar, or else, if Show sync activity is on, the last exchange each way that changed something ("Received 3 changes from firefly 1m ago · Sent 12 changes to Den just now", counting operations), unless a problem shows. It fades out 3 seconds after it last changed, unless something is running or wrong, and comes back when the pointer nears it.
* **Tooltips:** short, sentence-style fragments without a period ("Delete download"), saying only what the control and the text around it don't: its name, for one that shows only a symbol; else a warning or state, as "The only copy". Explanations go in the pane's text.
* **Modelessness:** no spontaneous alerts, after the original Macintosh guidelines: like stealing focus, an alert nobody asked for interrupts. An action a person takes is confirmed first only if it's hard to undo: removing a source (saying how many videos go, on every device, its files untouched), since only adding it again and looking for its videos anew undoes it; and deleting a download that's the only copy, which nothing undoes. What goes wrong shows in the status bar (and in a bar along the bottom of Settings) in words, never the core's error names, each source by its name ("Looking for new videos failed for art › Movies › 2160p (and 5 more): the server has nothing at that address."), until dismissed, until the next action of its kind (refreshing, changing the library, reading it) succeeds, or until the device gains or leaves a library.

### Apple TV

* **Data directory:** in the caches (the core's default on tvOS), the only place tvOS lets an app keep files, which it may purge; the seeds (`identity`, `user`, `library`) are kept in the Keychain too, and put back at launch, so a purge loses only what syncing and crawling rebuild.
* **Refreshing:** at launch, naming itself (the Apple TV's name) if it has no name, sharing the library (so its progress and watchlist reach the person's other devices), then syncing with devices found by DNS-SD, then crawling the sources itself.
* **Exchanges:** if Show Sync Activity is on, the last exchange with devices each way that changed something, shown for a few seconds in the corner after each.
* **Shelves:** a tab bar of Home (Continue Watching, then the watchlist, each row a focus section, so moving down from the tab bar enters the first row), Movies, Series (a cover per series, its progress over every season's running time), Watchlist, Watched, Settings, and Search (those two as symbols alone, so every tab fits, and Settings first, as tvOS shows no tab after search's); covers six to a row, as tvOS's lockups (borderless buttons, the cover's highlight effect lifting it; its name moved down by hand while focused, as the style moves a title only for an `Image`), with progress and watched marks, and a star if on the watchlist (a series', if any season is).
* **Settings:** as tvOS's Settings app lays its out, measured against it in the simulator at the same scale and kept as proportions of the screen (on tvOS's 1920-point screen: the picture, 540 points wide, centered at 528 by 506; the explanation 768 wide, low at 940; the list's plates from 1060 to 1840, under the tab bar, the left pane behind it; a subpage's title centered at 90.5, `.title2`, bold, tertiary, drawn by the page, as SwiftUI's navigation title sits lower and pushes the list down), its rows in the system's text size (`.headline`, larger than a form's own), its rows' text and headings inset 30 points in its plate, as the system's (`listRowInsets`), wider than a form's: the app's icon (`SettingsIcon`, flattened by [draw-icons.swift](draw-icons.swift) from the cinema-red gradient and `film.stack`) centered in the left half, and under it, small and gray, what the focused row does (or a problem leaving, whatever's focused), crossfading, in place of footers, and each row's accessibility hint, since VoiceOver doesn't reach what's shown only on focus; the list in the right half, a `Form` in the grouped style, so its rows, plates, and headings are the system's (each row on a rounded plate of one height, a toggle's state its value, headings small, uppercase, and bold: Names, Library), its rows without symbols. This Apple TV's name and its person's, each a button row (its title and value, `ValueLabel`, the value on one line, truncated, so rows keep one height, and a chevron, as the system's Name row has, though a keyboard opens) that, pressed, brings up the full-screen keyboard at once, titled with the row's name and holding the name: an unseen UIKit field (`KeyboardField`, hidden from VoiceOver in UIKit, as SwiftUI's `accessibilityHidden` doesn't reach it, and clipped to a point, as tvOS's fields keep a size of their own, whose plate showed through the focused row's) becoming first responder, since SwiftUI's fields open the keyboard only when pressed themselves, and one in a row draws a plate of its own within the row's, crowding the name; saved as it's submitted (a blank name ignored), Back leaving it as it was; Refresh Library, as at launch; Look for New Videos, the library's interval, as a row opening a page of its choices, as tvOS's Settings has them (the current one checked and focused first; choosing one sets it and goes back), a button pushing buttons (`navigationDestination`), since a picker's `.navigationLink` style opens an empty list, on a page of its own (the tab bar hidden, its title at the top), its row's chevron drawn as the system's (`ValueLabel`: 18 by 32 points, 32 after the value and 36 short of the plate's edge, scaling with the text), a form's own being smaller and farther from the value. Every row with a value is a `ValueLabel` (Show Sync Activity too, a button with the toggle trait, its state as its value, as SwiftUI's toggle can't stack): at accessibility text sizes, as the system's, its value goes under its title, rows grow to three lines' height (200 points, as the system's), and the picture shrinks to 316 points wide, centered at 344, the explanation running from under it. The names take the full-screen keyboard, the one public keyboard that lays itself out by General › Keyboard Layout (Linear or Grid) as the system's Name page does: that page is the private `UISystemInputViewController`, and a search controller's inline keyboard, the only public inline one, overflows a page under Grid; Show Sync Activity; and Leave This Library…, confirmed first (as ending it, with no one else in it), or asking who takes over if it's the founder's only device, once a refresh or sync under way is done, then returning to setup, or saying why it couldn't. Sources and people are managed on the Mac.
* **Pages:** a movie's, over a blurred backdrop of its cover: Play or Resume (Start Over before Resume), a Quality picker (the best it plays unless one's chosen; of one quality, its name as text), and the watchlist and watched marks, on one row, the picker beside what it plays; versions, and its description. A series': its seasons (the first not watched through outlined, specials last; each cover whole, fit and centered in its square), Play for the season's next episode, its Quality picker after Play as a movie's, and its episodes under an Episodes heading, described as the season's shown. The quality is the best it plays: MP4, MOV, or M4V (not MKV or ISO), up to 2160p on a 4K display, else up to 1080p.
* **Playing:** full screen in `AVPlayerViewController`, started once per request (fading the page re-hosts it, so not in a view's task), Play pressed again over the black ignored until the player's on screen; AVFoundation and AVKit are loaded as the shelves first show. The page (and the tab bar) fades to black while the stream warms up, the session made once the fade's done; then the display switches to the video's frame rate and range (asked of the window by the app, if Match Content is on), blanking the screen; then UIKit presents the player over the black (AVKit's views don't belong in SwiftUI's), unanimated and ready, so it shows no spinner; then its picture fades in as its sound rises, once it's playing, not merely asked to (surround passed through, encoded, to a receiver can't ramp, and comes at once). Going to the background (the TV button), it pauses, silent, and comes back paused (AVKit's own resume held off), its sound rising when it's played.

## Checking the interface

The Apple TV player runs in the tvOS simulator (an Apple TV 4K, 3rd generation, made for testing with `simctl create`), which reaches the LAN from the host. Install the debug build with `simctl install`, launch it with launch options prefixed `SIMCTL_CHILD_` (e.g., `SIMCTL_CHILD_CINEMATHEQUE_TAB=movies xcrun simctl launch DEVICE com.rbrian.cinematheque`), and capture it with `simctl io DEVICE screenshot`. An agent drives its remote through Xcode's MCP tools: `DeviceInteractionStartSession` (with the simulator's UDID; its advice to load a `device-interaction` skill in a subagent can be skipped), then `DeviceInteractionSynthesize` with `r up`, `r down`, `r left`, `r right`, `r select`, or `r menu` (Back), or no command to capture, each call returning a screenshot and a UI hierarchy, which marks the focused element `Focused` (count presses by it, as focus skips dimmed rows, and trust it over a screenshot taken mid-transition), and `DeviceInteractionEndSession` when done. The launch options reach states the remote would take many presses to. By hand, it runs in Device Hub, Xcode's simulator app (in `Xcode.app/Contents/Applications`).

Screenshots come from a macOS VM, run by terrarium from the `macos-27.2-quiet` layer, whose screen it captures without screen-recording permission on the host. Put the debug build's app into the guest, at `~/Cinematheque.app`, with media and the [command-line app](../cli/README.md) to serve it on the guest's loopback (`serve --media`), then open the app, to set up from scratch, or with a data directory in place and launch options, e.g., `open --env CINEMATHEQUE_SELECT=t/m/all-systems-red/2017 ~/Cinematheque.app`. During a tight loop of changes, keep the VM running and only replace the app (quit it, copy the new build in, reopen it), keeping the guest's media server and data directory; stop the VM when the work moves away from the interface. Drawing the window from within the app instead (`cacheDisplay`, or rendering its layers) misses macOS 26's floating sidebar.

## Findings

* Played from a Caddy server on a NAS, over Wi-Fi: HandBrake's `.m4v` files open in seconds, and seek, with their audio and subtitle tracks.
* Of 14 HandBrake files on a NAS, every one carried a JPEG cover (2:3 posters for movies, 667×1000; squares for TV, 800×800) and a description.
* A tile with both a double-click and a single-click gesture delays selection by the double-click interval; selecting is a plain tap, and playing a simultaneous double tap.
* SwiftUI's `VideoPlayer` failed to load when the app ran unbundled ("failed to demangle superclass of VideoPlayerView"); AppKit's `AVPlayerView` works either way.
