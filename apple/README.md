# Apple players

The players for Apple devices, in SwiftUI, on the [core](../core/README.md) through its C interface: macOS 15+, tvOS 18+, and iOS 18+ on iPhone. What they do is specified in [AGENTS.md](../AGENTS.md#apple-players); this file says how. The Mac app opens this device's data directory (`CINEMATHEQUE_DATA`, or the default), which it shares with the [command-line app](../cli/README.md).

## Building

Open [Cinematheque.xcodeproj](Cinematheque.xcodeproj) in Xcode and run the Cinematheque scheme on My Mac, an Apple TV, or a tvOS simulator; Product › Show Build Folder in Finder finds the app in DerivedData. Or, from the command line:

```sh
xcodebuild -scheme Cinematheque -configuration Release build
open "$(xcodebuild -scheme Cinematheque -configuration Release \
  -showBuildSettings | sed -n 's/^ *BUILT_PRODUCTS_DIR = //p')/Cinematheque.app"
xcodebuild -scheme Cinematheque \
  -destination 'generic/platform=tvOS Simulator' build
xcodebuild -scheme Cinematheque \
  -destination 'generic/platform=iOS Simulator' build
```

The project is in Xcode 27's format ([project.xcproj](Cinematheque.xcodeproj/project.xcproj), readable JSON, converted with `xcodebuild -convert-project "Xcode Project"`), so it needs Xcode 27 or later. One multiplatform target, Cinematheque, builds for macOS, tvOS, iOS (iPhone only, `TARGETED_DEVICE_FAMILY` 1), and their simulators; settings that differ are conditioned on the SDK (`[sdk=macosx*]`).

* **Sources:** the [Cinematheque](Cinematheque) folder, which Xcode keeps in sync, so new files need no project edits: [Shared](Cinematheque/Shared), and [macOS](Cinematheque/macOS), [tvOS](Cinematheque/tvOS), and [iOS](Cinematheque/iOS), each file wrapped in `#if os(…)`. A view each platform has its own of shares one type name (`Browser`), so shared code names it once; its files carry a platform suffix (`Browser+tvOS.swift`), as a target can't compile two files of one name.
* **Core:** the build phase runs [build-core.zsh](build-core.zsh), which builds the core with Zig (from `/opt/homebrew/bin` or `/usr/local/bin`) for the platform (the SDK as sysroot) and each architecture being built, so Release builds are universal. Debug builds build it ReleaseSafe too (about 52 seconds an architecture after a core edit, where Debug took 7), as Zig 0.17's `std` panics in Debug on an interrupted connect (see [DEVELOPMENT.md](../DEVELOPMENT.md)). It links each into one object exporting only `_cq_*` (`ld -r -exported_symbol '_cq_*'`), since the compiler runtime Zig bundles (for 128-bit floats) would otherwise clash with Xcode's. Swift imports it as `CCinematheque`, by the [module map](../core/include/module.modulemap).
* **Bundle:** [Info.plist](Cinematheque/Info.plist) is merged into the generated one and preprocessed (`#if TVOS`, defined for tvOS's SDKs), so `cinematheque://` is declared on tvOS alone. [Assets.xcassets](Cinematheque/Assets.xcassets) holds placeholder icons drawn by [draw-icons.swift](draw-icons.swift) (a cinema-red gradient and `film.stack`): the Mac's on its icon grid (a rounded square 824 of 1,024 across, as macOS sets a full-bleed square on a gray plate), and the Apple TV's brand assets (a two-layer icon, the Top Shelf, and Settings' `SettingsIcon`). A compiled catalog matters beyond looks: without one, tvOS's search keyboard faults (CoreUI's "unable to find a bundle").
* **Scheme:** shared, with `CINEMATHEQUE_DATA` ready but disabled (on iOS and tvOS, debug builds only, `Platform.prepareDataDir` taking it in place of the app's own), and `CA_DEBUG_TRANSACTIONS`, off, to log Core Animation used off the main thread.
* **Settings:** Xcode 27.2's recommended ones but the four [AGENTS.md](../AGENTS.md#apple-players) names: script sandboxing is off, as the build phase reads `../core` and Zig's cache; no App Sandbox, as the app shares its data directory with the command-line app; no hardened runtime until signing for distribution; and macOS 15. Swift code is main-actor isolated by default, with approachable concurrency; what crosses threads (the core's handle, decoded images) is `nonisolated`.
* **Signing:** ad hoc on the Mac; automatic on tvOS and iOS, so simulators need no team, and devices need a `DEVELOPMENT_TEAM`. It's in [Signing.xcconfig](Signing.xcconfig), not the target, as the target's settings outrank the file (a team left blank there hides the developer's). A developer's own settings go in `Local.xcconfig` beside it, included if present and ignored by Git. If Xcode's Signing editor writes into the target again, delete them there.
* **Version:** `MARKETING_VERSION` comes from [Version.xcconfig](Version.xcconfig), included by [Signing.xcconfig](Signing.xcconfig) and read by the command-line app's build; the core gets it by [build-core.zsh](build-core.zsh)'s `-Dversion`. The target sets none (editing General's Version writes one in: delete it).

## Sources

Shared:

* [Library.swift](Cinematheque/Shared/Library.swift): the library through the C interface (state, setting up, calling the core), with extensions by area: [Library+People.swift](Cinematheque/Shared/Library+People.swift) (pairing, names, devices), [Library+Sources.swift](Cinematheque/Shared/Library+Sources.swift) (sources, this Mac's folders, serving, refreshing), [Library+Downloads.swift](Cinematheque/Shared/Library+Downloads.swift) (the Mac's), [Library+Sync.swift](Cinematheque/Shared/Library+Sync.swift), and [Library+Progress.swift](Cinematheque/Shared/Library+Progress.swift). It passes string arrays as C arrays copied for the call (`withCStrings`), decodes JSON into [Models.swift](Cinematheque/Shared/Models.swift)'s types, and runs long operations off the main thread, reloading as they commit. What goes wrong becomes `problem`, a sentence (a long operation's first failure by server name, and how many more) with its kind, so only a success of that kind clears it.
* [ArtCache.swift](Cinematheque/Shared/ArtCache.swift): covers fetched by range request, scaled with ImageIO off the main thread (480 pixels for tiles, 1,200 for larger), kept in memory and on disk (`com.rbrian.cinematheque/covers` in the caches). A cover replaces its color at once (a fade wasn't worth it at any length tried); one in memory shows from the start, so scrolling back shows no color first.
* [Playback.swift](Cinematheque/Shared/Playback.swift): what to play (`PlayRequest`) and the queue, each entry with its item's other copies to try in turn; a Mac's download plays from its file (`Playback.downloads`).
* [PlaybackSession.swift](Cinematheque/Shared/PlaybackSession.swift): a queue in an `AVQueuePlayer`, streaming by byte ranges. It starts from the raced winner (`prefer`, racing later items in the background), swaps in an item's next copy when one doesn't load (`loaded`), and saves progress; no save in the first 10 seconds, where a resume's seek may not have landed. On the Mac, its first save reconciles downloads, so a series' next episode comes while this one plays. Each platform wraps it in its own view.
* [FadingIn.swift](Cinematheque/Shared/FadingIn.swift): starting playback: black while the session warms up paused (`PlaybackSession.begin`: loaded, sought, prerolled), then its `Curtain` rises as sound rises; leaving lowers it, saving the position where the fade ends. Fades take 0.5 seconds (`Platform.fade`); resuming starts 4 seconds early (`Platform.replay`).
* [TitlePresentation.swift](Cinematheque/Shared/TitlePresentation.swift): how titles and items read (facts, runtimes, Play and Resume labels, `Tile.seasonName`); `QualityChoice` (the best format the player plays, up to its display's resolution; `shortNames`); `TileMarks` and its marks (`DownloadedMark`, `ListedMark`, `WatchedMark`, green as tvOS's accent is white); `PlayButtons`, Start Over and Play or Resume, styled by platform; menu items shared (`WatchedItems`, `ListActions`); `ItemLine`, an item's row on the Apple TV and iPhone; `CoverProgress`, drawn by hand, as ProgressView's track can't be made translucent; `UnderCover`, a layout sizing what's under a cover by the cover, so a long name is cut short rather than widening its slot; and `Marks`: `ListsMenu` (named Lists whatever it's on, so nothing beside it moves) and `WatchedToggle`.
* [SetupView.swift](Cinematheque/Shared/SetupView.swift): first run: `OfferedCode` polls the core until paired, its digits in `CodeBoxes`; on the Mac (and iPhone), `SetupForm`, 520 × 400 points with the scene sized to its content, its `Choice` rows drawn by `ChoiceStyle` as Xcode's welcome window draws its own, Create a Library the default. Beside them, what adding a device shares: `Nearby`, which polls for devices offering; `Looking`, while none is; and on the iPhone and Apple TV, `AddingDevices`, the choosing and pairing their `NewDevices` lists.
* [Confirmations.swift](Cinematheque/Shared/Confirmations.swift): Settings' confirmations, alike on every platform: leaving (`Leaving`, `confirmsLeaving`), and removing someone or a source (`confirmsRemoving`, which on the Mac stops serving a folder, by `Library.remove`).
* [SourceSettings.swift](Cinematheque/Shared/SourceSettings.swift), on the Mac and iPhone: a source's quality setting (`SourceQualityPicker`) and its unavailable folders (`UnavailableFolders`). Servers are added by `Library.addServer`, everywhere.
* [Shelf.swift](Cinematheque/Shared/Shelf.swift): the shelves (names, symbols, tiles, search, counts, empty text; a series' shelf counts episodes too) and their orders (`ShelfOrder`, applying the core's places), which the Mac's View › Sort By chooses per shelf (`SortCommand`, by a focused binding, kept as JSON in `@AppStorage`); one tile per title, for browsers showing a series as one; Home's rows (`homeRows`, the Top Shelf's too) and search, alike everywhere. The Mac's Watching is stored as `inProgress`.
* [CinemathequeApp.swift](Cinematheque/Shared/CinemathequeApp.swift): the app: its library, opened from the platform's data directory; the root view (unopened, setting up, or browsing), naming, serving, and refreshing at launch and once set up; on macOS, player windows, Settings, and the File menu's commands.

* [Launch.swift](Cinematheque/Shared/Launch.swift), debug builds only: launch options (see [AGENTS.md](../AGENTS.md#debugging)).

## In detail

How the players do what [AGENTS.md](../AGENTS.md#apple-players) specifies, and why.

### Both

* **Start Over** uses `backward.end.fill`, before Resume as a timeline starts at its leading edge; marking unwatched also forgets the position, so it's the one way to start over.
* **Copies:** racing asks every copy at once (`HEAD`, 1.5 seconds, or 250 ms more after one answers, for a better-placed one, as a NAS waking); one that failed in the last 10 minutes is asked last, so a sleeping server costs a second, not a network timeout. Sources' names are looked up once a launch's refresh is done (`cq_race_warm`), as a first lookup may outlast a race. With one copy, there's no race.
* **Syncing after a change** waits for changes to stop a second and for any long operation under way (begun, perhaps, before the change), then calls `cq_sync_known`, reaching every device at once. Syncs on a timer or coming to the front (an Apple TV app returns from the home screen, never relaunched) aren't shown as activity.
* **Reloading** during a crawl polls `cq_data_version` each second, reading, decoding, and sorting tiles and sources off the main thread (`reloadApart`), as they're the whole catalog: on the main thread, a crawl of 100,000 files left the Apple TV's main thread idle a tenth of the time.

### macOS

* **Grid:** cells are 148 points at any width (`.adaptive`, equal minimum and maximum), as stretching ones resized every cover at each column change while the inspector animated. Each shelf has its own scroll view, as one left scrolled past a shorter shelf's end drew nothing. Covers fit whole (`CoverImage`'s `fit`), dimmed by `unavailable`.
* **Rows:** `CoverGrid.Rows` works out every row's place and height before drawing (from AppKit's line heights; a movie's tile keeps a year line whether it has one), drawing only rows within a screen of the view, in content of the whole height. A lazy grid guessed undrawn rows' heights, so the thumb stepped back as it paged and jumped when let go. Paging by the track jumps rather than animates (`NSScrollAnimationEnabled` stored off if unset, as AppKit reads it past registered defaults), as SwiftUI's scroll position lagged AppKit's mid-animation and pulled the thumb back. Rows on screen are those clear of the toolbar and status bar; selecting scrolls by offsets from the content's top at rest.
* **Keeping its place:** the top title is restored only when the column count changes (`onGeometryChange` of `columns`), not every width an animation passes, as scrolling each frame flashed the scroll bar.
* **Group by Series:** `GroupCommand` toggles `groupsSeries`, the grid remade as it changes, keeping its topmost title; `Rows.init(series:)` builds a tile per series from `perTitle`'s tiles. The season line stays blank for a first season alone (a miniseries, or one cut short, as Firefly) so tiles line up; the year goes right-aligned on it, or on the name's line when it's blank, an em apart as `ViewThatFits` measures, telling The Tick (1994) from (2001).
* **Bands:** the selected series (`pointed`) is open unless `collapsed`, its seasons on a `Band` (a rounded rectangle tinted with the primary color, pointing at its column) in a row after its series', its height known from its seasons' count. Opening keeps the series selected by key, the inspector showing it whole; closing a band whose season is selected selects its series. Room for the tallest band (`most`) is kept at the grid's end, and series tiles and seasons are remade only when tiles change (`RowCache`), not as bands open.
* **Motion:** opening and closing animate together (`bandMotion`, a quarter second). The band fades as one (`compositingGroup`, else the tint shows through its seasons); seasons' captions have no transition of their own, as they lagged. A band entering or leaving as another moves above it is offset by its row's movement (`bandEnter`; `bandLeave` drawn a frame ahead, as a leaving view takes its transition from its last drawing), since a view coming or going is drawn where it ends, not moved with its row.
* **Layering:** series rows are drawn on the grid's opaque ground (`background` by `backing`, from the gap above each down), each over those before, so rows after a band slide off it as it opens, revealing it top-down, as the web client's band grows in flow. Unrolling the band itself (a clipping animation or a scaled mask) stalled midway; fades and offsets, run by the window server, don't.
* **Scrolling to a band:** opening a series below another's band, it moves up as that band closes; once it has, `Viewport.glide` animates the clip view just enough to show the band (series first if both don't fit), as `ScrollPosition` scrolls at once even in an animation, and scrolling as rows moved jumped ahead of them.
* **Tiles:** a name's help appears only when cut short (`ViewThatFits`). `CoverImage` keeps placeholder and cover in one view, showing one, so a cover arriving adds no view (an added one, as a band opened, faded in where it would end rather than sliding).
* **Keys** are taken by `onKeyPress`, as the scroll view took move commands before `onMoveCommand` saw them, and read the selection as the grid last set or saw it (`current`), as a handler's binding read stale. Down from an open series enters its band beneath it; from a band, Left and Right leave its ends to neighboring series, Up and Down its first and last rows to the rows above and below.
* **Inspector:** applied outside the split view, as in Apple's WWDC23 example, so it's full height, and attached only while shown (`Inspecting`): hidden, its collapsed divider took the window's last 16 points over the scroll bar, and dragging there opened it. Its toggle is the app's, declared twice, one shown at a time: in the grid's toolbar after search while hidden, and in the inspector's `.toolbar` after a flexible `ToolbarSpacer` (macOS 26+; before, at its start) while shown, so it stays far right. SwiftUI's own toggle came and went between launches, and the system's View › Show Inspector goes with it, so `InspectorCommand` (by a focused binding) is the app's. The quality picker has a row of its own so choosing changes only what's below it; Lists and watched are labeled where they fit, else icons.
* **Downloading:** no control appears or disappears (a hidden gauge keeps its place; what doesn't apply is dimmed). Show in Finder selects the download first, else what's in its folders; menus list places in sections by what opening does, qualities highest first, with symbols by `.titleAndIcon`, and a warning triangle where it wouldn't fit, as menus can't be colored. Download stays beside Show in Finder, as a folder may be a mounted share, worth downloading or not. A season's choice is a SwiftUI pop-up at Regular size, so it opens under the pointer and matches its menu; its Available line is a Picker item made unselectable by `selectionDisabled()` (`disabled()` leaves it selectable), its tag no choice.
* **Toolbar:** search is AppKit's (`SearchField`, an `NSSearchField` 160 points wide in the grid's own toolbar item; Escape clears it; Find focuses it by `SearchFocus`), as `searchable` puts it at the window's trailing end over the inspector (`DefaultToolbarItem(kind: .search)` doesn't move it). The 960-point minimum (`browsingSize`) keeps title, action, and search, as SwiftUI drops an item that doesn't fit, and a minimum on the grid alone squeezed the sidebar. `Library.forgetWatched` marks each watched tile's items unwatched, then reloads once. Refresh Library Fully is `modifierKeyAlternate`, calling `cq_crawl_full`, as retagging a file in place leaves its folder's time unchanged.
* **Playing:** the toolbar is hidden by AppKit (`NSToolbar.isVisible`), as SwiftUI's hiding hides the window buttons too; the title bar is transparent. Back is a round chevron the height of the window buttons' row, glass on macOS 26+; `NowPlaying` ("Archer · S1E9 · Job Offer") sits after it where macOS 26 puts a title, over a faint gradient. `KeyedPlayerView` takes keys by a monitor on its window, as `AVPlayerView` handles arrows (a frame at a time) in a view of its own, and tracks the pointer itself, as SwiftUI's hover tracking over it kept AVKit's controls hidden. Captions follow the preferred languages, beeping if there are none. The display is kept awake by an activity of the app's own, as AVPlayer's didn't hold. Player windows aren't restored at launch.
* **Settings:** Look for videos and a source's quality sit under Advanced; names to skip are the command-line app's to change. Folders on this Mac are kept in the app's settings and served at `http://<Mac>.local:<port>/<folder>/`. Downloads' folder defaults to `~/Movies/Cinematheque` as Apple's TV app keeps `~/Movies/TV`. New Devices' Yours becomes the default (Return) once the code's whole, the box ring gone; a wrong code shakes as the login window does. No one's added in People, as an advertisement proves nothing.
* **Modelessness** follows the original Macintosh guidelines: an alert nobody asked for interrupts, as stealing focus does. Errors are in words, never the core's error names ("Looking for new videos failed for art › Movies › 2160p (and 5 more): the server has nothing at that address.").

### Apple TV

* **Home:** `Browser` is one `NavigationStack` rooted at `HomeView`, with no tab bar, so nothing above the content takes focus. `Sections` is a focus section across the page; focus starts on its first, as `defaultFocus` and `prefersDefaultFocus` were both passed over at the stack's root. Each `Row` and each list heading's line is a focus section, so moving down enters the nearest. A heading is its link (to `ListPage` by `ListPageID`) in the plain style, whose pill grows outward so its text aligns with plain headings (the borderless style lifted its chevron alone); a See All over the second cover drew focus rightward at every heading. Rows are 360 points high, a grid's 2:3 cover's.
* **Navigation:** a link's value is typed (`SeriesSeasons`, `ListPageID`, `Section`, `Tile`), as destinations are found by type, not under `AnyHashable`. `SectionPage` puts its name as the grid's first line.
* **Series:** `SeasonsView`'s Play names the season to watch (`Library.nextSeason`), its details read before drawing so it's there to take focus; `markSeriesWatched` marks the whole series.
* **Lists:** `ListPage` puts its name in the grid, aligned and scrolling with the covers (a navigation title stayed inset at the top), and its actions in `PosterGrid`'s footer; it dismisses itself once its list is gone, having nothing to focus. Naming opens the full-screen keyboard at once (`KeyboardField`), as an alert's field brought the keyboard up over the alert.
* **Covers:** borderless buttons, the highlight effect lifting the cover; the name is moved down by hand while focused, as the style moves a title only for an `Image`. A series' star shows if any season is listed. Seasons show everywhere but the Series section and Search, so lists show what they hold.
* **Settings** are measured against tvOS's Settings app in the simulator, kept as proportions of the 1920-point screen: the picture 540 wide, centered at 528 by 506; the explanation 768 wide, at 940; plates from 1060 to 1840; a subpage's title centered at 90.5 (`.title2`, bold, tertiary), drawn by the page, as a navigation title sits lower. Rows use `.headline` and 30-point insets (`listRowInsets`), as the system's, larger than a form's. The list is a grouped `Form`, centered while it fits by `SpareHeight`, which reads its height from the UIKit table beneath, as a form keeps no scroll anchor and an unscrolled list reports no geometry. The explanation crossfades and is also each row's accessibility hint, as VoiceOver doesn't reach what shows only on focus.
* **Values:** `ValueLabel` keeps a value on one truncated line, so rows keep one height; at accessibility sizes the value goes under the title, rows grow to 200 points, and the picture shrinks to 316 wide, centered at 344. Its chevron is drawn as the system's (18 by 32, 32 after the value, 36 short of the edge, scaling with text), as a form's own is smaller and farther off.
* **Names:** a row's press makes `KeyboardField`, an unseen UIKit field, first responder, opening the full-screen keyboard at once, as SwiftUI's fields open it only when pressed themselves, and one in a row draws a plate of its own. It's hidden from VoiceOver in UIKit (SwiftUI's `accessibilityHidden` doesn't reach it) and clipped to a point (tvOS fields keep a size, whose plate showed through). The full-screen keyboard is the one public keyboard honoring General › Keyboard Layout, as the system's Name page (the private `UISystemInputViewController`) does; a search controller's inline keyboard overflows under Grid. A blank name is ignored; Back leaves it unchanged.
* **Choices:** Look for New Videos is a button pushing buttons (`navigationDestination`), as a picker's `.navigationLink` style opened an empty list. Pressing a row acts on it, as tvOS's rows have no buttons: a `confirmationDialog` to remove, or rename by `KeyboardField`. `NewDevices` polls `Nearby` every 2 seconds and takes a code on `.numberPad`; Add Server uses `.URL`, `http://` prefilled.
* **Pages:** a season's `Neighbor` buttons, at an end the chevron alone, dimmed, focus moving past it (a dimmed button kept focus); their row is a focus section, so Up from Play reaches them. Episodes are described as the season shows.
* **Playing:** started once per request, not in a view's task, as fading the page re-hosts it; Play pressed over the black is ignored until the player shows. AVFoundation and AVKit load as the shelves first show. The session is made once the fade to black is done; then the app asks the window to match the video's frame rate and range (if Match Content is on); then UIKit presents the player over whatever's frontmost, unanimated and ready, so it shows no spinner of its own, UIKit's large white spinner standing in on the black. `fullScreenCover` isn't used, as AVKit adds views (snapshots while its controls animate) beside the player that SwiftUI's hosting view doesn't take. The controller is presented first, black, then given its curtain (a black view in `contentOverlayView`, over the picture, under the controls) and the session, as views made before it's in a window have no scene; it's detached before dismissal. The picture fades in once playing, not merely asked to (surround passed through to a receiver can't ramp, and comes at once). Each item's metadata carries its cover (`commonIdentifierArtwork`) for the info panel and Now Playing. Its start's steps are logged with times (`Playing`, then `Starting #n: raced copies…, loaded…, sought…, prerolled…`, and `matched the display`).
* **Leaving:** after the fade, controls hidden, the display gets its own mode back; during that switch (some 3 seconds, blank), the player is stopped and dismissed over the black page, which fades in once it's done. In the background it pauses silent and returns paused, AVKit's own resume held off; the sync loop idles while the app isn't active, so nothing redraws as the system snapshots it.

## Checking the interface

The Apple TV player runs in the tvOS simulator (an Apple TV 4K, 3rd generation, made for testing with `simctl create`; `Mockup …` simulators run the mock library, `Production …` ones a developer's own, as [tools/README.md](../tools/README.md) says), which reaches the LAN from the host. Install the debug build with `simctl install`, launch it with launch options prefixed `SIMCTL_CHILD_` (e.g., `SIMCTL_CHILD_CINEMATHEQUE_TAB=movies xcrun simctl launch DEVICE com.rbrian.cinematheque`), and capture it with `simctl io DEVICE screenshot`. The launch options reach states the remote would take many presses to. An agent drives its remote through Xcode's MCP tools: `DeviceInteractionStartSession` (with the simulator's UDID; its advice to load a `device-interaction` skill in a subagent can be skipped); then `DeviceInteractionSynthesize` with `r up`, `r down`, `r left`, `r right`, `r select`, or `r menu` (Back), or with no command, to capture; and `DeviceInteractionEndSession` when done. Each call returns a screenshot and a UI hierarchy, which marks the focused element `Focused`: count presses by it, as focus skips dimmed rows, and trust it over a screenshot taken mid-transition. By hand, it runs in Device Hub, Xcode's simulator app (in `Xcode.app/Contents/Applications`).

Screenshots come from a macOS VM, run by terrarium from the `macos-27.2-quiet` layer, whose screen it captures without screen-recording permission on the host. Put the debug build's app in the guest at `~/Cinematheque.app`, with media and the [command-line app](../cli/README.md) serving it on the guest's loopback (`serve --media`), then open the app, to set up from scratch, or with a data directory in place and launch options, e.g., `open --env CINEMATHEQUE_SELECT=t/m/all-systems-red/2017 ~/Cinematheque.app`. In a tight loop of changes, keep the VM running and replace only the app (quit it, copy the new build in, reopen it), keeping the guest's media server and data directory; stop the VM when work moves away from the interface. Drawing the window from within the app instead (`cacheDisplay`, or rendering its layers) misses macOS 26's floating sidebar.

## Findings

* Played from a Caddy server on a NAS, over Wi-Fi: HandBrake's `.m4v` files open in seconds, and seek, with their audio and subtitle tracks.
* Of 14 HandBrake files on a NAS, every one carried a JPEG cover (2:3 posters for movies, 667×1000; squares for TV, 800×800) and a description.
* A tile with both a double-click and a single-click gesture delays selection by the double-click interval; selecting is a plain tap, and playing a simultaneous double tap.
* SwiftUI's `VideoPlayer` failed to load when the app ran unbundled ("failed to demangle superclass of VideoPlayerView"); AppKit's `AVPlayerView` works either way.
