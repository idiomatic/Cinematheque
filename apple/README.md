# Apple players

The players for Apple devices, in SwiftUI, on the [core](../core/README.md) through its C interface:

* **macOS** (macOS 15 or later): it sets up and manages a library, browses it by cover art, and plays copies straight from their sources, keeping the person's progress and watchlist. It opens this device's home (`CINEMATHEQUE_HOME`, or the default), which it shares with the [device](../cli/README.md).
* **Apple TV** (tvOS 18 or later): it pairs as a person's device or joins their library, syncs with devices and crawls the sources itself, browses by cover art with the remote, and plays full screen, keeping progress by the same rules.

## Building

Open [Cinematheque.xcodeproj](Cinematheque.xcodeproj) in Xcode and run the Cinematheque scheme on My Mac, an Apple TV, or a tvOS simulator; Product › Show Build Folder in Finder finds the app in DerivedData. Or, from the command line:

```sh
xcodebuild -scheme Cinematheque -configuration Release build
open "$(xcodebuild -scheme Cinematheque -configuration Release \
  -showBuildSettings | sed -n 's/^ *BUILT_PRODUCTS_DIR = //p')/Cinematheque.app"
xcodebuild -scheme Cinematheque \
  -destination 'generic/platform=tvOS Simulator' build
```

The project is in Xcode 27's format ([project.xcproj](Cinematheque.xcodeproj/project.xcproj), readable JSON, converted with `xcodebuild -convert-project "Xcode Project"`), so it needs Xcode 27 or later. It has one multiplatform app target, Cinematheque, for macOS, tvOS, and tvOS's simulator; settings that differ by platform are conditioned on the SDK (e.g., `[sdk=macosx*]`):
* **Sources:** the [Cinematheque](Cinematheque) folder, which Xcode keeps in sync, so new files need no project edits: [Shared](Cinematheque/Shared) for both platforms, and [macOS](Cinematheque/macOS) and [tvOS](Cinematheque/tvOS), each file of which is wrapped in `#if os(macOS)` or `#if os(tvOS)`. A view each platform has its own of shares its type's name (`Browser`), so shared code names it once; its files are suffixed by platform (`Browser+tvOS.swift`), since a target can't compile two files of one name.
* **Core:** the build phase runs [build-core.zsh](build-core.zsh), which builds it with Zig (from `/opt/homebrew/bin` or `/usr/local/bin`) for the platform (macOS, tvOS, or its simulator, with the SDK as sysroot) and each architecture being built, so Release builds are universal, and links each into one object exporting only the C interface (`ld -r -exported_symbol '_cq_*'`), since the compiler runtime Zig bundles (which the core needs for 128-bit floats) would otherwise clash with Xcode's. Swift imports it as `CCinematheque`, by the [module map](../core/include/module.modulemap) beside its header.
* **Bundle:** [Info.plist](Cinematheque/Info.plist), merged into the generated one, allows plain HTTP and Bonjour (`_cinematheque._tcp`) on the local network, where sources and devices are; [Assets.xcassets](Cinematheque/Assets.xcassets) holds placeholder icons, drawn by [draw-icons.swift](draw-icons.swift) (a cinema-red gradient and the `film.stack` symbol): the Mac's, on its icon grid (a rounded square 824 of 1,024 across, since macOS sets a full-bleed square on a gray plate), and the Apple TV's brand assets (its icon in two layers, for parallax, and the Top Shelf). A compiled catalog matters beyond looks: without one, tvOS's search keyboard faults looking for it (CoreUI's "unable to find a bundle").
* **Scheme:** shared, with `CINEMATHEQUE_DATA` ready, disabled, for running on another library.
* **Settings:** Xcode 27.2's recommended ones (its macOS app template's), but for four, on purpose: script sandboxing is off for the core's build phase, which reads `../core` and Zig's cache; there's no App Sandbox, since the app shares this device's data directory in `~/Library/Application Support`; the hardened runtime waits for signing for distribution; and the app runs on macOS 15 or later. Swift code is isolated to the main actor by default, with approachable concurrency; what crosses threads (the core's handle, decoded images) is marked `nonisolated`.
* **Signing:** on the Mac, ad hoc; on tvOS, automatic, so the simulator needs no team, and an Apple TV needs `DEVELOPMENT_TEAM` for tvOS. A developer's own settings, such as `DEVELOPMENT_TEAM`, go in `Local.xcconfig` beside [Signing.xcconfig](Signing.xcconfig), which includes it if present; Git ignores it, so they stay out of commits.

## Sources

Shared:

* [Library.swift](Cinematheque/Shared/Library.swift): the library through the C interface, decoding its JSON (status, tiles, a title's details, sources, members, the watchlist), and running long operations (crawling, syncing, describing) off the main thread, reloading as they commit. What goes wrong becomes `problem`, a sentence (a long operation's first failure by its server's name, and how many more), with its kind, so only a success of the same kind clears it.
* [ArtCache.swift](Cinematheque/Shared/ArtCache.swift): covers fetched by range request, scaled with ImageIO off the main thread (480 pixels for tiles, 1,200 for larger covers), and kept in memory and on disk (the app's caches, `com.rbrian.cinematheque/covers`); until one loads, its placeholder, rendered by the core from its ThumbHash and scaled up, or without one, a color of its own with its title. A cover replaces its placeholder at once (a fade, tried at 3, 0.3, and 0.1 seconds, wasn't worth it); one in memory shows from the start, so scrolling back shows no placeholder.
* [Playback.swift](Cinematheque/Shared/Playback.swift): what to play (`PlayRequest`), and the queue: a movie, or a season's episode in progress (the latest, if several), else its next unwatched, and the rest after it; each entry with its item's other copies, the quality's then its other qualities', to try in turn. A download on this Mac plays from its file, first (`Playback.downloads`).
* [PlaybackSession.swift](Cinematheque/Shared/PlaybackSession.swift): playing a queue in an `AVQueuePlayer`, streaming by byte ranges, starting from the copy whose server answers first (`prefer`, by the core's copy racing, the queue's later items in the background), and putting an item's next copy in its place when one doesn't load (`loaded`), saving the progress every 10 seconds (but not within the first 10, where a resume's seek may not have landed) and where it's paused or closed (so stopping within the first 10 seconds deletes it), reloading tiles' progress when it stops, and at each item's end, marking it watched; each player wraps it in its platform's view.
* [FadingIn.swift](Cinematheque/Shared/FadingIn.swift): how playback starts on every platform: the screen fades to black (0.5 seconds) while the session warms up, paused (`PlaybackSession.begin`: the first item loaded, sought to its position, and prerolled), then it plays and its `Curtain` rises: the picture fades in as the sound rises from silence (on a television, after the display has switched to the video's mode, while paused). Leaving lowers it before what follows. Every fade, of picture or sound, takes 0.5 seconds (`Platform.fade`); resuming starts 4 seconds (`Platform.replay`) before where playing was left.
* [TitlePresentation.swift](Cinematheque/Shared/TitlePresentation.swift): how titles and items read on every platform (facts, runtimes, episode names, Play and Resume labels, and Start Over's rewind symbol, before Resume), the quality to play (`QualityChoice`: the best format the player plays, up to its display's resolution), `CoverMarks`, a cover's star (on the watchlist) and check (watched, on green, since tvOS's accent color is white), and `Marks`, the watchlist and watched buttons, the latter showing its state (Watched or Unwatched), which pressing toggles.
* [SetupView.swift](Cinematheque/Shared/SetupView.swift): the first run: pairing by a code this device shows (`OfferedCode`, polling the core until paired, its digits in `CodeBoxes`, a squircle each in two groups of three, as the field that takes it shows them), to be another of your devices or to join someone's library, or creating a library, as a form on the Mac, and on tvOS as `SetupFlow`.
* [Shelf.swift](Cinematheque/Shared/Shelf.swift): the shelves (Home, those begun and not watched; Movies; Series; Watchlist; Played, a smart folder of everything with progress, from which a tile's context menu removes its progress): their names, symbols, tiles (a series' by season), search, counts, and what an empty one says; and one tile per title, for browsers that show a series as one. The Mac's In Progress and Watched split Played (it has no Home), and its Downloaded is its only.
* [CinemathequeApp.swift](Cinematheque/Shared/CinemathequeApp.swift): the app, for both platforms: its library, opened from the platform's home; the root view, showing no home, setting up, or browsing, and at launch and once set up, naming this device and person, serving, and refreshing; and on macOS, player windows, Settings, and Refresh Library (⌘R), which syncs, then crawls.
* [Platform.swift](Cinematheque/Shared/Platform.swift): what differs by platform outside the interface: the home (on tvOS, with its seeds kept in the Keychain), and the device's and person's default names.
* [Launch.swift](Cinematheque/Shared/Launch.swift), in debug builds only: launch options for driving the app unattended (see [AGENTS.md](../AGENTS.md)).

macOS:

* [Browser+macOS.swift](Cinematheque/macOS/Browser+macOS.swift): `Browser`: shelves (Movies, Series, Watchlist, Played) beside a lazy grid of covers in fixed cells, movies 2:3 and seasons square under their series (covers fit whole, `CoverImage`'s `fit`), with watched marks and progress bars, dimmed when every copy is on a drive that isn't there (`unavailable`); the tiles in view go to the core to be described first while a crawl runs. Each shelf has its own scroll view (one left scrolled past the end of a shorter shelf drew nothing), which returns to the shelf's topmost title, and keeps it at the top when the grid's width changes, as when the inspector opens or closes. Cells are one fixed width (`.adaptive` with equal minimum and maximum), since stretching ones resized every cover at each column change while the inspector animated; and the top title is put back only when the column count changes (`onGeometryChange` of `columns`), since scrolling at every frame flashed the scroll bar. Tiles count as visible once half on screen (`onScrollVisibilityChange`), and leave on disappearing too, since a lazy grid drops a tile it scrolls far past without saying so. `StatusBar` floats over the bottom of the grid: counts or what went wrong, and a long operation's progress (`cq_steps`, read twice a second while one runs), fading 3 seconds after it last changed unless something is running or wrong, and returning when the pointer nears it; the grid's bottom margin lets its last row clear it. `ProblemBar` shows what went wrong along the bottom of Settings. Neither is ever an alert. The toolbar holds the inspector's toggle (⌥⌘I) and, last, search: SwiftUI pins its toolbar search to the trailing edge, and the guidelines put both at the trailing edge without ordering them, so the toggle goes just before search, as in Photos (a custom field could put the toggle last, but would lose the native one's behavior).
* [InspectorView.swift](Cinematheque/macOS/InspectorView.swift): the selected tile's larger cover, Play or Resume (a season from its episode in progress, else its next unwatched, the rest queued), the watchlist and watched marks (borderless), progress meters each with `ClearPosition` beside it, forgetting the position (`Library.clearPosition`, the watched mark kept), metadata, and a movie's versions or a season's episodes (season 0 as Specials, each playing with the rest queued), described on demand, the quality picker (`qualityPicker`, by `QualityChoice.shortNames`) in their heading. Downloading (`DownloadControls`): a movie's row (Download with its size, a `DownloadGauge`, a trash button), a season's (the series' Download pop-up, a `DetailedPopUp` giving each choice's size at its trailing edge, a gauge, a trash button), and each episode's `DownloadMark` and context menu (`DownloadMenuItems`, also a movie tile's).
* [PlayerView.swift](Cinematheque/macOS/PlayerView.swift): the playback session in AppKit's `AVPlayerView`: `WindowPlayer`, filling the library's window, with Back (Escape), showing while the pointer moves and for 3 seconds after, and back at the queue's end; or `PlayerView`, a window of its own, titled for the item playing, which closing stops. `PlayAction` (the `play` environment value) chooses between them by ⌘. The toolbar is hidden through AppKit (`NSToolbar.isVisible`), since SwiftUI's hiding a window's toolbar hides its window buttons too. `KeyedPlayerView` takes the keyboard (Space, F, M, and the arrows, 10 seconds back and forward) by a key monitor on its window, since AppKit's player view handles the arrows (a frame at a time) in a view of its own, and tracks the pointer itself: SwiftUI's hover tracking over it keeps AVKit's controls from showing. In the title bar's row, fading with the controls as QuickTime Player's does: the window buttons, Back, and `NowPlaying`, what's playing, centered.
* [Settings](Cinematheque/macOS/Settings), a file to a pane, each pane listing devices nearby polling for them (`Nearby`), no keys anywhere, and no addresses outside Advanced:
  * [ManageView.swift](Cinematheque/macOS/Settings/ManageView.swift): the four panes' tabs, and what they share (`RemoveButton`, `Footer`, `Looking`, `Nearby`).
  * [PeoplePane.swift](Cinematheque/macOS/Settings/PeoplePane.swift): members by name, you renamable in place (`MemberRow`), and those waiting to join.
  * [DevicesPane.swift](Cinematheque/macOS/Settings/DevicesPane.swift): your devices, each renamable in place (this Mac's name re-advertised) and, but for this Mac, removable (`DeviceRow`); sharing; New Devices; and, under Advanced, devices by address.
  * [PairRow.swift](Cinematheque/macOS/Settings/PairRow.swift): a new device offering to pair, to be yours or to join, paired by the code it shows (typed into `CodeField`: `CodeBoxes`, showing the code's length before it's typed, over an invisible field that takes focus, typing, and pasting, digits alone; the sixth digit pairs, and a wrong code shakes it clear (`Shake`), focused again) and moved, animated, into Your Devices or People.
  * [SourcesPane.swift](Cinematheque/macOS/Settings/SourcesPane.swift): folders on this Mac, chosen with an open panel and served while the app runs, those not there shown as unavailable and served once back, and servers, each added by a button of its own (Add Folder… and Add Server…, whose `SourceSheet` takes a server's address as Finder's Connect to Server does); Look for videos and Refresh Library; a server's unavailable folders, listed in its sheet, each with Remove Videos.
  * [DownloadsPane.swift](Cinematheque/macOS/Settings/DownloadsPane.swift): the folder, what it holds, and whether watched downloads go at once.

Apple TV:

* [Keys.swift](Cinematheque/tvOS/Keys.swift): the data directory's seeds kept in the Keychain, since tvOS may purge the caches that hold it.
* [SetupFlow+tvOS.swift](Cinematheque/tvOS/SetupFlow+tvOS.swift): setting up as tvOS apps do: the app's name over three large choices, each step a screen of its own; pairing as another device and joining someone's library each show a pairing code (`PairingStep`).
* [Browser+tvOS.swift](Cinematheque/tvOS/Browser+tvOS.swift): `Browser`: the tab bar, Home's rows, the poster grid, search, and what a refresh is doing.
* [SettingsView.swift](Cinematheque/tvOS/SettingsView.swift): Settings: the Apple TV's name and its person's, Refresh Library, and Leave This Library…, with its confirmation and, for the founder's only device, its choice of who takes over.
* [TitleViews.swift](Cinematheque/tvOS/TitleViews.swift): a movie's page and a series', with their marks and episodes; seasons' covers fit whole in their squares (`CoverImage`'s `fit`).
* [TVPlayer.swift](Cinematheque/tvOS/TVPlayer.swift): the playback session full screen in `AVPlayerViewController`, with titles and descriptions for its info panel; presented by UIKit over whatever's frontmost, not by SwiftUI's `fullScreenCover`, since AVKit adds views of its own (snapshots, as its controls animate) beside the player's, which SwiftUI's hosting view doesn't take; presented first, black, then given its curtain (a black view in its `contentOverlayView`, over the picture and under the controls) and the session, since its views made before it's in a window have no scene; detached before it's dismissed. Each item's metadata carries the cover (`commonIdentifierArtwork`), which Now Playing asks for. Playback logs its start's steps and their times (`Playing`, then `Starting #n: raced copies…, loaded…, sought…, prerolled…`, and `matched the display`) under `com.rbrian.cinematheque`, `playback`, to tell where a slow start goes. The shared scheme has `CA_DEBUG_TRANSACTIONS`, off, to log where Core Animation is used off the main thread. While the app isn't active, the sync loop does nothing, so nothing redraws as the system snapshots the app going to the background.

## Checking the interface

The Apple TV player runs in the tvOS simulator (an Apple TV 4K, 3rd generation, made for testing with `simctl create`), which reaches the LAN from the host. Install the debug build with `simctl install`, launch it with launch options prefixed `SIMCTL_CHILD_` (e.g., `SIMCTL_CHILD_CINEMATHEQUE_TAB=movies xcrun simctl launch DEVICE com.rbrian.cinematheque`), and capture it with `simctl io DEVICE screenshot`; the remote can't be driven from a script, hence the options.

Screenshots come from a macOS VM, run by terrarium from the `macos-27.2-quiet` layer, whose screen it captures without screen-recording permission on the host. Put the debug build's app into the guest, at `~/Cinematheque.app`, with media and the [command-line app](../cli/README.md) to serve it on the guest's loopback (`serve --media`), then open the app, to set up from scratch, or with a data directory in place and launch options, e.g., `open --env CINEMATHEQUE_SELECT=t/m/all-systems-red/2017 ~/Cinematheque.app`. During a tight loop of changes, keep the VM running and only replace the app (quit it, copy the new build in, reopen it), keeping the guest's media server and data directory; stop the VM when the work moves away from the interface. Drawing the window from within the app instead (`cacheDisplay`, or rendering its layers) misses macOS 26's floating sidebar.

## Findings

* Played from a Caddy server on a NAS, over Wi-Fi: HandBrake's `.m4v` files open in seconds, and seek, with their audio and subtitle tracks.
* Of 14 HandBrake files on a NAS, every one carried a JPEG cover (2:3 posters for movies, 667×1000; squares for TV, 800×800) and a description.
* A tile with both a double-click and a single-click gesture delays selection by the double-click interval; selecting is a plain tap, and playing a simultaneous double tap.
* SwiftUI's `VideoPlayer` failed to load when the app ran unbundled ("failed to demangle superclass of VideoPlayerView"); AppKit's `AVPlayerView` works either way.
